# Algol 68 (GNU, SUPPER stropping) for VS Code

Syntax highlighting for Algol 68 as GNU ga68 and a68j understand it with
`-fstropping=supper`: reserved words in lower case (`begin`, `int`,
`if`), modes and operators as bold words with a capital first letter
(`Node`, `Int_list`, `ABS`, `HAS`).

It started from [jlguenego/vscode-algol68](https://github.com/jlguenego/vscode-algol68)
(ISC). That grammar knows only UPPER stropping and a good twenty
keywords; this one is written anew, generated by
`a68j/tools/gen_tmlanguage.py` and checked against the real scanner
(see `docs/editor.md` in the a68j directory).

## Installation

Without the Marketplace it is enough to copy the folder:

- Windows: `%USERPROFILE%\.vscode\extensions\algol68-supper`
- Linux/macOS: `~/.vscode/extensions/algol68-supper`

then restart VS Code. Or install the packaged `algol68-supper-0.2.1.vsix`:
Extensions view, menu "…", "Install from VSIX…", or
`code --install-extension algol68-supper-0.2.1.vsix`.

## What is highlighted

| What | Example | Scope |
|---|---|---|
| control words | `begin if then for do od case esac goto` | `keyword.control` |
| modules | `module def fed postlude access pub nest egg` | `keyword.other.module`, `keyword.control.import` |
| declarers | `mode op prio proc ref flex heap loc long short struct union` | `storage.type`, `storage.modifier` |
| standard modes | `int real bool char string void bits bytes compl sema file channel` | `storage.type.primitive` |
| constants | `true false nil skip empty` | `constant.language` |
| word operators | `andth orel is isnt of at` | `keyword.operator.wordlike` |
| modes of your own | `Node`, `Int_list`, `F` | `entity.name.type` |
| operators of the prelude | `ABS UPB LWB ODD MOD ENTIER REPR …` | `support.function.operator` |
| operators of your own | `MAX`, `HAS`, `TOSTRING` | `entity.name.function.operator` |
| modules in `module`/`access` | `access Lists, Hashmaps` | `entity.name.namespace` |
| procedure definitions | `proc area = …`, `f = (int n) int: …` | `entity.name.function` |
| identifiers of the prelude | `puts whole fixed sqrt max_int long_pi stdout …` | `support.function`, `support.constant` |
| labels | `done:`, `goto done` | `entity.name.label` |
| numbers | `42`, `1 000`, `1.5e-3`, `.25`, `16rff`, `2r1010` | `constant.numeric.*` |
| strings | `"a""b'n'(u00e4)"` | `string.quoted.double`, escapes `constant.character.escape` |
| comments | `{ … { nested } … }` | `comment.block` |
| pragmats | `[[ include "x.a68" ]]` | `meta.preprocessor.pragmat` |
| format texts | `$3d$` (split, not compiled by ga68) | `meta.format` |
| errors | `×`, `¬` outside strings, `2r03`, `foo_Bar` | `invalid.illegal` |

**Mode or operator?** Algol 68 does not tell the two kinds of bold words
apart by their spelling. The grammar follows the usual style: capitals
only (two characters or more) is an operator, everything else a mode.
After `mode`, `op`, `module` and `access` the context decides. So an
operator of a single letter (except `I`) appears as a mode, and a mode in
capitals (`mode NODE`) as an operator.

## Editor features

- `{ … }` as a block comment (Ctrl+Shift+A).
- Bracket pairs `( )`, `[ ]` and `begin/end`, `if/fi`, `case/esac`, `do/od`, `def/fed`.
- Indentation after `begin then else elif do in out ouse def`.
