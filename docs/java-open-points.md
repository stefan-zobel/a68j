# Java integration: module ideas

The state of the Java integration (`-fnest-java`, `nest Java "…"` formal
holes, the modules `Lists` and `Hashmaps`) is described in
[java-modules.md](java-modules.md). This file collects ideas for further
modules backed by Java APIs. The open points of the integration itself
are done, and so are the idea B1, the modules `Texts` and `Regex`
([texts.md](texts.md), [regex.md](regex.md)), the idea B2, the module
`Files` ([files.md](files.md)), the integers of the idea B3, the module
`Bigints` ([bigints.md](bigints.md)), and the idea B4, the module `Times`
([times.md](times.md)).

## Ideas for Java modules

Modules in the style of `Lists` and `Hashmaps`, where a Java API fills a
gap in the Algol 68 library (the prelude of the Revised Report and its
transput). They are ordered by how much they would help in everyday
programs, in my estimate.

Two rules from java-modules.md apply to all of them:

- A Java object is an opaque Algol 68 name, `mode X = ref X_object` with
  `mode X_object = struct (int x_java_object)`, as for `Stringlist`.
- A module that should be usable together with `Lists` must not declare
  a priority for `AT`, `INDEX`, `HAS` or `REMOVE`; it takes
  `access pub Lists` instead (java-modules.md, "`Lists` and `Hashmaps`
  together").

### B3. `Bigdecimals`: decimals of any precision

The integers of this idea are done: the module `Bigints`
([bigints.md](bigints.md)). What remains are decimals.

**The gap.** `real` has single precision in ga68 and a68j and
`long real` double precision. There are no exact decimal fractions, and
`Bigints` has no `/`.

**The Java side.** `java.math.BigDecimal` with a `MathContext` for the
precision and the rounding of division, square root and so on.

**How it fits.** A module `Bigdecimals` with `access pub Bigints`, as
`Hashmaps` makes `Lists` public, and a mode `Bigdecimal` on a class of
its own in `a68j.jlib`. Its operators would be generated by
`tools/gen_bignums.py` like those of `Bigints`, as a second kind of
number in its tables, with the mixed operators for `Bigint`, `int` and
`long real`. Open questions:
- where the precision is set (a procedure of the module, or a parameter
  of `/`);
- how `ROUND`, `ENTIER` and the output in the style of `fixed` and
  `float` fit.

### B6. `Digests`: checksums and encodings

**The gap.** MD5, SHA-1, SHA-256, CRC-32 and Base64 need unsigned 32-bit
arithmetic and bytes, which Algol 68 expresses only with effort through
`bits`. Rosetta Code has `md5`, `crc-32` and `base64-encode-data`.

**The Java side.** `java.security.MessageDigest`, `java.util.zip.CRC32`,
`java.util.Base64`, `java.util.HexFormat`.

**How it fits.** A few procedures and no new modes: a digest of a string
(its UTF-8 bytes) as hexadecimal text, `crc32` as a `long int`, Base64
encoding and decoding of a string. Open question: whether bytes beyond
strings are needed (a row of `int`, or the contents of a file through
`Files`).

### B7. Priority queues and sorted maps

**The gap.** Dijkstra, A*, event simulation and "the k smallest" need a
heap or an ordered map; programs write their own each time.

**The Java side.** `java.util.PriorityQueue`, `java.util.TreeMap`.

**How it fits.** Modes generated by `tools/gen_lists.py` and
`tools/gen_hashmaps.py` or a generator next to them, for the element and
key modes of `Lists` and `Hashmaps`. The order is the natural one of the
mode; a queue of structures ordered by a field would need a key
procedure, as a priority of type `int` or `real` next to the element.
The rules above on `AT`, `INDEX`, `HAS` and `REMOVE` apply.

### B8. Images

**The gap.** Algol 68 has no graphics. Up to 26 Rosetta Code originals
(Mandelbrot set, dragon curve, Sierpinski curves, the bitmap tasks)
contain `draw` or `make device`, most likely the drawing procedures of
Algol 68 Genie (plotutils), which `-fgenie` does not provide.

**The Java side.** `java.awt.image.BufferedImage`, `java.awt.Graphics2D`,
`javax.imageio.ImageIO` (PNG), headless.

**How it fits.** A mode for an image with pixels, lines, rectangles,
circles and text, written to a PNG file. Under `-fgenie` the procedures
of Algol 68 Genie under their names, writing the image to a file instead
of a window. First step: check the drawing API of Algol 68 Genie 3.13.4
in its source.

### B9. External processes

**The gap.** Running a command and reading its output. The command-line
arguments are covered by the POSIX module of ga68; `system` of Algol 68
Genie (`execute-a-system-command`) is not available.

**The Java side.** `java.lang.ProcessBuilder`.

**How it fits.** A procedure that runs a command (a row of strings, no
shell) and yields its exit status, one that also yields its standard
output as a string, and `system` of Algol 68 Genie for `-fgenie`. Small,
but rarely needed.

### B5. Less central

HTTP (`java.net.http.HttpClient`) and JSON would also fit technically.
JSON has no parser in the JDK, so it would need a library on the class
path (`-fjava-classpath`). Both are less central for Algol 68 programs.
