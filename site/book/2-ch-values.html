2 Values, types and variables

This chapter introduces the building blocks of every program: values and their types, constants and variables, the arithmetic and logical operators, assignment, and simple input and output. One idea in it is more important than the others and is the key to much of the language: a variable in Algol 68 is a name for a reference to a memory cell, and the language says so openly. Section 2.6 explains what this means.

2.1 Types

Every value in a program has a type (mode). The type determines which values are possible and which operations apply. Algol 68 has four primitive types:

Type Values Examples
int whole numbers 0, 42
real floating-point numbers 3.5, 1e6
bool truth values true, false
char single characters "a", "7"

The type string for sequences of characters is not primitive: it is a resizable array of char (Chapter 7). It can be used in the same simple ways as the primitive types, though, and this chapter does so.

The range of int and the precision of real depend on the implementation. The standard library provides constants that describe them, among them max_int, the largest int, and small_real, the smallest real that gives a result different from 1 both when it is added to 1 and when it is subtracted from 1:

access Genie_Transput
begin
   print (("max_int    ", max_int, newline));
   print (("small_real ", small_real, newline));
   print (("long max_int ", long_max_int, newline))
end
max_int    +2147483647
small_real +1.192093e -7
long max_int +9223372036854775807

Implementation note.  In ga68 and a68j, int has 32 bits and real is a 32-bit floating-point number (single precision, about 7 decimal digits). The types long int and long real have 64 bits. In Algol 68 Genie, int has 64 bits and real is a 64-bit floating-point number. Precision variants are the subject of Chapter 6.

2.2 Literals

A value written directly in the program text is a literal (denotation):

access Genie_Transput
begin
   print ((0, 42, 1 000 000, newline));
   print ((3.5, " ", .25, " ", 1e6, " ", 2.5e-3, newline));
   print (("a", "Z", "_", """", newline));
   print ((true, false, newline))
end
         +0        +42   +1000000
+3.500000e +0 +2.500000e -1 +1.000000e +6 +2.500000e -3
aZ_"
TF

An int literal is a sequence of digits. It has no sign: in -5, the minus is an operator applied to the literal 5. Blanks may appear between the digits, so 1 000 000 is a single literal; commas may not.

A real literal has a decimal point, an exponent, or both: 3.5, .25, 1e6, 2.5e-3. There must be at least one digit after the point, so 5. is not a literal; 5.0 is. The letter of the exponent may be written e or E.

A char literal is a single character between double quotes. A double quote itself is written twice: """" is the literal for the character ". The same rule applies to strings: "say ""hi""" is the string say "hi".

The two bool literals are true and false. When print writes a truth value, it writes T or F.

2.3 Names

The names that a program gives to its constants, variables and procedures are identifiers (identifier, tag). An identifier begins with a lower-case letter and continues with lower-case letters, digits and underscores: x, x2, max_value. Reserved words cannot be used as identifiers.

Capital letters have a meaning of their own (Section 1.4): a word that begins with a capital letter is a type name or an operator. A name in the style of other languages, such as maxValue, is therefore read as the identifier max followed by a type name Value, and the compiler complains about the type:

access Genie_Transput
begin
   int maxValue = 100;
   print ((maxValue, newline))
end
identifier-case.a68:3:11: error: indicant Value has not been declared properly

2.4 Constants

A declaration of the form

int days_per_week = 7

binds the identifier days_per_week to the value 7, for the rest of the block in which the declaration appears. Such a binding cannot be changed; days_per_week is a constant. The Report calls this form an identity declaration, since it declares that the identifier and the value are identical: wherever days_per_week is used, it stands for 7. It corresponds to const in C and JavaScript, to final in Java and to let in Rust.

The value need not be known when the program is compiled. Any expression of the right type can stand on the right-hand side, including one that uses other constants or reads input. Several constants can be declared at once, separated by commas; declarations are separated by semicolons:

int days_per_week = 7;
int weeks = 52, extra_days = 1;
int days_per_year = days_per_week * weeks + extra_days;
real g = 9.81;
char separator = ",";
bool verbose = false;
print ((days_per_year, separator, fixed (g, 0, 2), separator, verbose, newline))
       +365,9.81,F

An attempt to change a constant is an error, found by the compiler:

access Genie_Transput
begin
   int n = 10;
   n := 11;
   print ((n, newline))
end
constant-assign.a68:4:4: error: int secondary does not yield a name

The message is phrased in the terms of the Report: a name is what this book calls a reference, and the message says that n is not a reference, so nothing can be assigned to it. Section 2.6 explains this.

2.5 Variables

A variable is declared with := instead of =, or with no initial value at all:

access Genie_Transput
begin
   int count := 0;
   real total := 0.0;
   count := count + 1;
   total := total + 2.5;
   count := count + 1;
   total := total + 4.0;
   print (("count = ", count, ", total = ", total, newline))
end
count =          +2, total = +6.500000e +0

The declaration int count := 0 creates a variable that holds an int, with the initial value 0. The assignment count := count + 1 replaces the value held by count with a new value. Several declarations can be joined with commas, but the type may be left out only if the next declaration is of the same kind: int x = 5, y := 6 is an error (“mixed identity-declaration and variable-declaration”), whereas int x = 5, int y := 6 is allowed. The declarations joined by commas are carried out in an unspecified order, so one of them must not use another (Section 3.4).

A variable declared without an initial value, as in real x, holds no defined value until a value is assigned to it. Using it before then is an error that the compiler does not detect. A string variable, and a string inside an array or record variable, is the exception: it starts out as the empty string, since a string is a resizable array whose initial bounds are 1 and 0 (Section 7.1), and an empty array has no elements that could be undefined.

Implementation note.  ga68 and a68j give such a variable an initial value: zero, false or a blank character. A program should not rely on this, since other implementations do not.

2.6 What a variable is: references

In most languages a variable is a primitive concept: a name that refers to a place in memory whose content can change. Algol 68 builds variables from two simpler concepts, and makes both visible.

The first concept is allocation. The expression loc int allocates a fresh memory cell that can hold an int, on the stack of the current block, and yields a reference to that cell. The type of a reference to an int cell is ref int, read “reference to int”. A reference is a value like any other: it can be bound to an identifier, passed to a procedure or stored in another cell. The Report calls a reference a name and an allocation a generator.

The second concept is the constant declaration of the previous section. Together they give a variable:

int a := 5;                    { the short form }
ref int b = loc int := 5;      { what the short form means }
a := a + 1;
b := b + 1;
print ((a, b, newline))
         +6         +6

The declaration ref int b = loc int := 5 allocates a cell, assigns 5 to it, and binds b to the reference. The short form int a := 5 means exactly the same, and a program normally uses the short form. But the long form shows what the identifier of a variable stands for: not the number in the cell, but the reference to the cell. The type of a is ref int, not int.

Since a reference is a value, it can be bound to a second name. The second name then refers to the same cell, and an assignment through it changes the variable:

int a := 5;
ref int alias = a;          { another name for the cell of a }
alias := 99;
print ((a, newline))
        +99

prints 99. Nothing has been copied: the declaration binds the name alias to the reference that a stands for.

This explains the error message of the previous section. The left-hand side of an assignment must be a reference, of type ref int when an int is assigned. A constant declared as int n = 10 has the type int; it is the number 10 itself, and there is nothing to assign to.

Programmers who know C++ will recognize the idea: b behaves like a C++ reference int& b to a cell. In Rust, b would be a &mut i32, which needs an explicit * to read the cell; Algol 68 reads the cell implicitly where a value is needed (Section 2.10). Programmers who know Java or Python can think of the reference as the hidden storage location behind every variable; Algol 68 simply gives it a type. The distinction between a value and a reference to a cell holding that value is the source of most of the power of the language’s type system, and later chapters return to it often: references to references, references in records, references returned by functions, and how long the cell behind a reference lives.

2.7 Arithmetic

The arithmetic operators on int and real are:

Operator Meaning Operand types
+ - * addition, subtraction, multiplication int, real
/ division int, real; the result is real
% integer division, truncating toward zero int
MOD remainder, never negative int
** power int or real base, int exponent
- (unary) negation int, real

Note that / always yields a real, even for two int operands, so n := 4 / 2 is rejected for an int variable n; integer division is %. The remainder a MOD b lies between 0 and ABS b - 1 even if a is negative, unlike the % operator of C, Java or JavaScript:

access Genie_Transput
begin
   int a = 17, b = 5;
   print ((a + b, a - b, a * b, newline));
   print ((a / b, newline));
   print ((a % b, a MOD b, newline));
   print ((-a % b, -a MOD b, newline));
   print ((a ** 2, " ", 2.5 ** 2, newline))
end
        +22        +12        +85
+3.400000e +0
         +3         +2
         -3         +3
       +289 +6.250000e +0

The power operator requires an int exponent, which may be negative if the base is a real: 2.0 ** -1 is 0.5. A real power, such as a square root, is computed with the functions of the standard library (sqrt, exp, ln), which Chapter 6 describes.

Implementation note.  An int result that does not fit into an int is undefined by the Report. In ga68 and a68j, it wraps around silently: max_int + 1 gives  − 2147483648. The result of an int raised to a negative power, such as 2 ** -1, is undefined as well.

2.8 Precedence

Every binary operator has a precedence (priority) from 1 to 9. An operator of higher precedence binds more tightly: 2 + 3 * 4 is 2 + (3 * 4). Operators of equal precedence are applied from left to right: 10 - 4 - 3 is (10 - 4) - 3. The standard operators have the following precedences:

Precedence Operators
9 I (complex numbers, Chapter 6)
8 **, UP, LWB, UPB
7 *, /, %, MOD, ELEM
6 +, -
5 <, <=, >=, >
4 =, /=
3 AND
2 OR
1 +:=, -:=, *:=, /:=, %:=, …

Two rules differ from what most current languages do. First, ** is applied from left to right like every other operator, so 2 ** 3 ** 2 is (23)2 = 64, not 29 = 512. Second, every unary operator binds more tightly than every binary operator. In -2 ** 2, the minus applies to the 2 first, so the result is (−2)2 = 4:

access Genie_Transput
begin
   print ((2 + 3 * 4, (2 + 3) * 4, newline));
   print ((10 - 4 - 3, 2 ** 3 ** 2, newline));
   print ((-2 ** 2, -(2 ** 2), newline))
end
        +14        +20
         +3        +64
         +4         -4

When in doubt, parentheses make the intended order explicit, and the programs in this book use them wherever the order might surprise a reader. Older programs, and many on Rosetta Code, write some operators as words: OVER for %, PLUSAB for +:=, and so on (Appendix A). Chapter 5 shows how a program declares operators of its own and their precedences.

2.9 Comparisons and logical operators

The comparison operators =, /= (not equal), <, <=, >, >= compare two numbers, or two characters in the order of their character codes, and yield a bool. The logical operators are AND, OR and the unary NOT:

access Genie_Transput
begin
   int x = 7;
   print ((x > 5, " ", x = 7, " ", x /= 7, newline));
   print ((x > 0 AND x < 10, " ", x < 0 OR x > 100, " ", NOT (x = 7), newline));
   print (("a" < "b", " ", "Z" < "a", newline))
end
T T F
T F F
T T

Since AND has a lower precedence than the comparisons, x > 0 AND x < 10 needs no parentheses. Applied to two truth values, = tests whether they are equal and /= is the exclusive or; (a < 0) = (b < 0) tests whether a and b have the same sign.

Pitfall.  NOT is a unary operator and binds more tightly than every binary operator, so NOT x = 7 means (NOT x) = 7, which the compiler rejects for an int x:

not-prec.a68:4:12: error: monadic operator NOT int has not been declared

The test is written NOT (x = 7) or x /= 7. Programmers who know Python, where not binds loosely, fall into this easily. Similarly, x < y < z is not a chained comparison: x < y is a bool, which cannot be compared with a number.

AND and OR are ordinary operators: both operands are evaluated before the operator is applied, as with every operator. They do not “short-circuit” like && and || in C or Java. The GNU dialect of Algol 68, which ga68 and a68j implement, adds the short-circuit forms andth and orel, which evaluate their right operand only when it is needed. They bind more weakly than every operator, and a chain of them needs parentheses: a andth (b andth c) (Appendix B). The following program shows the difference; it uses a small procedure check that prints a line before it returns its argument (procedures are the subject of Chapter 5):

access Genie_Transput
begin
   proc check = (bool b) bool: (print (("checked", newline)); b);
   print ((false AND check (true), newline));
   print ((false andth check (true), newline))
end
checked
F
F

2.10 Implicit conversions

In the program of Section 2.6, a has the type ref int, and yet a + 1 is allowed, although + is defined for int and not for references. The compiler inserts an operation that reads the cell: it converts the reference into the value it refers to. Such an automatic change of type is an implicit conversion (coercion), and this one is called dereferencing (dereferencing).

Algol 68 has six kinds of implicit conversion; this chapter needs two. The second is widening (widening): an int is converted into a real where a real is required. Both conversions can apply one after the other: in r := n below, the variable n is first dereferenced to an int, which is then widened to a real:

access Genie_Transput
begin
   int n := 3;
   real r := 2;                 { int to real: widening }
   r := n;                      { again: n is read, then widened }
   print ((n + 1, " ", r / 2, newline));
   print ((n + 0.5, " ", n < 3.5, newline))    { mixed operands }
end
         +4 +1.500000e +0
+3.500000e +0 T

There is no implicit conversion in the other direction, from real to int, since it would lose information:

access Genie_Transput
begin
   int i = 2.5;
   print ((i, newline))
end
no-narrowing.a68:3:12: error: real cannot be coerced to int in a strong-unit

The message, again in the terms of the Report, says that a real cannot be converted to int in a “strong-unit”. A unit is an expression; strong describes the place where the expression appears.

This is the last important idea of the chapter: which implicit conversions are allowed depends on where an expression stands. Algol 68 distinguishes five kinds of place, called conversion contexts (syntactic positions, contexts). The right-hand side of a declaration or an assignment is a strong context, where all conversions are allowed, since the required type is known. An operand of an operator is a firm context, where widening is not allowed, since the operator to apply is chosen by the types of its operands and is not known in advance. The operator ROUND, for example, is defined for a real operand only, and an int operand is not widened to make it fit:

access Genie_Transput
begin
   int n = 3;
   print ((ROUND n, newline))
end
round-int.a68:4:12: error: monadic operator ROUND int has not been declared

How then can n + 0.5 work, with an int and a real operand? Not by widening: the standard library simply defines the arithmetic and comparison operators for each combination of int and real operands (Revised Report, Section 10.2.3.5). Chapter 7 describes all six implicit conversions and all five contexts.

2.11 Assignment

An assignment x := e evaluates e and stores its value in the cell that the reference x refers to. An assignment is itself an expression: its value is the reference on the left-hand side. That makes a := b := 7 possible: it assigns 7 to b, and the result, the reference b, is dereferenced and its value assigned to a. The two sides of an assignment are evaluated in an unspecified order (Section 3.4).

The compound assignment x +:= e adds e to the value of x and stores the result in x; it is short for x := x + e, except that x is evaluated only once. Similar operators exist for the other arithmetic operators: -:=, *:=, /:= (for a real variable), %:= and %*:= (the MOD form). They are operators of precedence 1, so x +:= 1 + 2 adds 3. Their value, like that of an assignment, is the reference on the left-hand side.

Unlike the assignment, these are ordinary operators, and like all operators of the same precedence they are applied from left to right:

int a := 2, b := 1;
a +:= b +:= 3;              { (a +:= b) +:= 3 }
print ((a, b, newline))
         +6         +1

prints 6 and 1: a +:= b +:= 3 is (a +:= b) +:= 3, and b is not changed. A chain of assignments a := b := 3, in contrast, groups to the right. And n +:= x for an int variable n and a real x is rejected, for the same reason as n := n + x.

access Genie_Transput
begin
   int a, b;
   a := b := 7;                    { assigns 7 to b, then to a }
   print ((a, b, newline));
   int total := 10;
   total +:= 5;  total *:= 2;  total -:= 1;
   print ((total, newline));
   int k := 17;
   k %:= 5;
   print ((k, newline))
end
         +7         +7
        +29
         +3

2.12 Explicit conversions and other operators

A real is converted into an int with one of two operators. ENTIER x is the largest integer not greater than x (the floor). ROUND x is the integer nearest to x. Characters are converted to and from their integer codes with ABS and REPR. A few more operators complete the set used in this chapter:

Operator Result
ENTIER x the largest int not greater than the real x
ROUND x the int nearest to the real x
ABS x the absolute value of an int or real
SIGN x  − 1, 0 or 1, according to the sign of x
ODD n true if the int n is odd
ABS c the character code of the char c
REPR n the character with the code n 
access Genie_Transput
begin
   print ((ROUND 2.5, ROUND -2.5, ROUND 2.4, newline));
   print ((ENTIER 2.5, ENTIER -2.5, newline));
   print ((ABS -7, " ", ABS -2.5, SIGN -7, " ", ODD 7, newline));
   print ((ABS "A", " ", REPR 66, newline))
end
         +3         -3         +2
         +2         -3
         +7 +2.500000e +0         -1 T
        +65 B

Implementation note.  The Report does not say whether a number exactly halfway between two integers, such as 2.5, is rounded up or down. ga68 and a68j round it away from zero: ROUND 2.5 is 3 and ROUND -2.5 is  − 3.

2.13 Comments and layout

In the convention of this book, a comment is text between braces, { like this }. Comments can be nested: { a { nested } comment } is one comment. The layout of a program, its spaces and line breaks, is free: a program can be written on one line or spread over many. In the stropping of this book, spaces are not allowed inside an identifier or a reserved word, but may appear between the digits of a number. The Report allows spaces inside identifiers as well, which is why it and older texts write max int where this book writes max_int.

Implementation note.  The Report encloses a comment in two # symbols, or between two of the bold words comment or co. In the stropping convention of this book, ga68 and a68j accept only braces. Algol 68 Genie accepts #…#, CO…CO and COMMENT…COMMENT, but not braces. These comments cannot be nested: a comment ends at the next symbol of the kind that began it.

2.14 Simple input and output

The procedure print writes a list of values to the standard output. Each value is written in a standard layout: an int with its sign, in a field wide enough for max_int (11 characters in ga68 and a68j), a real in scientific notation, a bool as T or F, and a char or a string as it is. Apart from the padding of an int, no separators are inserted; a program that wants spaces between numbers prints them. For more control, three procedures convert a number into a string:

  • whole (n, w) converts the int n into a string of width w. A width of 0 gives a string just as wide as needed; a positive width gives a string of exactly that width, with a sign; a negative width gives that width without a plus sign.

  • fixed (x, w, d) converts the number x into a string of width w with d digits after the decimal point. Again, width 0 means “as wide as needed”.

  • float (x, w, d, e) converts x into scientific notation with an exponent of e digits (Chapter 9).

access Genie_Transput
begin
   int n = 42;
   real x = 3.14159;
   print ((n, " ", x, " ", true, newline));
   print ((whole (n, 0), "|", whole (n, 6), "|", whole (-n, 0), newline));
   print ((fixed (x, 0, 2), "|", fixed (x, 8, 3), "|", fixed (-x, 0, 1), newline))
end
        +42 +3.141590e +0 T
42|   +42|-42
3.14|  +3.142|-3.1

A number that does not fit into the given width is not printed in a wider field: whole (12345, 3) yields three asterisks (Section 9.8).

Implementation note.  The print of the Report writes a blank before every number that does not begin a line. ga68, a68j and Algol 68 Genie leave it out, which is why the outputs in this book show numbers directly after a preceding string.

The procedure read reads values from the standard input into variables. Numbers are separated by blanks or line breaks. The procedures read_int and read_real, an extension of Algol 68 Genie that Genie_Transput also provides, read a single value and return it, which is convenient for initializing a constant:

access Genie_Transput
begin
   int a, b;
   real c;
   read ((a, b, c));
   print ((a + b, " ", c * 2, newline));
   int d = read_int;
   print ((d, newline))
end

With the input

3 4
1.5
  99

the program writes

         +7 +3.000000e +0
        +99

A number is read after skipping blanks and line breaks, but a char is read as it is: a blank is a character. At the end of a line, reading a char moves on to the first character of the next line; the line break itself is never read as a character. The layout procedure space skips a single character, so a date written as 7/3/1975 can be read into three numbers:

int day, month, year;
read ((day, space, month, space, year));
print ((whole (year, 0), "-", whole (month, 0), "-", whole (day, 0), newline))
1975-3-7

prints 1975-3-7.

2.15 A complete program

The last program of this chapter reads a temperature in degrees Fahrenheit and converts it to degrees Celsius. The output shown is for the input 98.6:

access Genie_Transput
begin
   { Read a temperature in degrees Fahrenheit and print it in Celsius. }
   real fahrenheit;
   read (fahrenheit);
   real celsius = (fahrenheit - 32) * 5 / 9;
   print ((fixed (fahrenheit, 0, 1), " F is ",
           fixed (celsius, 0, 1), " C", newline))
end
98.6 F is 37.0 C

Writing (fahrenheit - 32) * (5 / 9) would also have worked, since / yields a real even for two int operands; with integer division, 5 % 9 would have been 0.

Exercises

The answers are at the end of the book.

  1. Which of the following are int literals, which are real literals, and which are neither? 12, -3, 1 000, 1,000, 2., .5, 3e2, 0.0.

  2. What are the values of 17 % 5, -17 % 5, 17 MOD 5, -17 MOD 5 and 17 / 5?

  3. What are the values of 2 + 3 * 4 ** 2 and -3 ** 2?

  4. Explain the difference between int n = 10 and int n := 10. What is the type of n in each case?

  5. Write the declaration real x := 1.5, y without the short form, using loc.

  6. Which of the following are correct, given int i := 1 and real r := 2.5? (a) r := i (b) i := r (c) i := ROUND r (d) r := ROUND i

  7. After int a := 1, b := 2, what are the values of a and b after a := b := a + b?

  8. Why does the compiler reject maxCount := 0, even if a variable max_count has been declared?

  9. What does int x := 1; ref int r = x; r := r + 1; print (x) print?

  10. Add parentheses to show how a < b AND x > 0 = y > 0 OR NOT done is grouped.

  11. What are the values of 2.0 ** -2 and ABS (-7 MOD 3)? Why is NOT n = 0 rejected for an int n?

Programming problems

  1. Read a number of seconds and print it as hours, minutes and seconds.

  2. Read the three coefficients of a quadratic equation whose roots are real, and print the roots (sqrt computes a square root).

  3. Read a character and print its code, the next character, and whether it is a digit ("0" <= c AND c <= "9").

  4. Read an amount of money in cents and print the smallest number of coins of 50, 20, 10, 5, 2 and 1 cents that make it up.

  5. Easter. Read a year and print the date of Easter Sunday, computed with the anonymous Gregorian algorithm (Meeus/Jones/Butcher), which needs only % and MOD.

  6. Day of the week. Read a date written as dd/mm/yyyy and print the day of the week as a number, using Zeller’s congruence. Where does it matter that MOD never yields a negative result?

  7. Clock. Read an hour from 0 to 23 and print it on a 12-hour clock with AM or PM, without if: the hour is (h + 11) MOD 12 + 1. (Hint: REPR and ABS can compute the letter.)

  8. Rounding money. Read an amount as a real, round it to cents with ROUND, and print euros and cents with % and MOD. Try a negative amount, and an amount above 100000 with the 32-bit real of ga68 or a68j. What goes wrong, and why should money not be kept in a real?
