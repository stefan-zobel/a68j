6 More built-in types and the standard library

Chapters 2 to 5 used four primitive types. This chapter introduces the remaining built-in types of the language: complex numbers, numbers of greater or smaller precision, bit sets and byte strings. It closes with a survey of the constants and functions of the standard library. Much of the chapter depends on the implementation, since the precision of numbers does; where it does, the text says what ga68, a68j and Algol 68 Genie provide.

6.1 Complex numbers

The type compl holds a complex number, a pair of real values for the real and the imaginary part. The binary operator I builds a complex number from its two parts: 1 I 2 is 1 + 2i. The arithmetic operators +, -, * and / work on complex numbers, also mixed with int and real operands, and = and /= compare them. Further operators give the parts and properties of a complex number:

Operator Result
RE z, IM z the real and the imaginary part
ABS z the absolute value |z|
ARG z the argument (angle), between  − π and π
CONJ z the complex conjugate
a I b the complex number a + bi 
proc show = (compl z) string:
   fixed (RE z, 0, 3) + (IM z < 0 | " - " | " + ")
      + fixed (ABS IM z, 0, 3) + "i";
compl z = 1 I 2, w = 3 I -1;
print ((show (z + w), "   ", show (z * w), "   ", show (z / w), newline));
print ((fixed (ABS (3 I 4), 0, 3), " ", fixed (ARG (0 I 1), 0, 4), " ",
        show (CONJ z), newline));
compl r := 2.5;                 { a real is widened to compl }
r *:= 0 I 1;
print ((show (r), newline))
4.000 + 1.000i   5.000 + 5.000i   .100 + .700i
5.000 1.5708 1.000 - 2.000i
.000 + 2.500i

The function show formats a complex number for printing. A real (and therefore an int) is widened to compl where a complex number is required, so compl r := 2.5 is allowed; this is the second step of the widening that Chapter 2 introduced.

The standard library declares compl as a record, mode compl = struct (real re, im), so re of z selects the real part of a complex variable and can be assigned to, and compl z = (1, 2) is a record literal. Two details catch the unwary: I has the highest precedence, 9, so 2 * x I y means 2 * (x I y); and complex numbers have no order, so there is no <.

Implementation note.  With ga68 a program that uses the complex operators must be linked with the static libga68, which is the default: the shared library (-shared-libga68) does not export them, and the program fails when it is linked. Genie_Transput does not print complex numbers directly, which is why the example formats them itself; the print of the Report and of Algol 68 Genie prints the two parts.

As an application, the following program solves quadratic equations, whose roots may be complex. The discriminant decides whether the square root is real or imaginary; the if balances its two branches to compl.

access Genie_Transput
begin
   { The roots of a x^2 + b x + c, real or complex. }
   proc show = (compl z) string:
      fixed (RE z, 0, 3) + (IM z < 0 | " - " | " + ")
         + fixed (ABS IM z, 0, 3) + "i";
   proc roots = (real a, b, c) void:
   begin
      real d = b * b - 4 * a * c;
      compl root = (d >= 0 | sqrt (d) | 0 I sqrt (-d));
      compl x1 = (-b + root) / (2 * a), x2 = (-b - root) / (2 * a);
      print ((show (x1), "   ", show (x2), newline))
   end;
   roots (1, -3, 2);
   roots (1, 2, 5);
   roots (2, 0, 8)
end
2.000 + .000i   1.000 + .000i
-1.000 + 2.000i   -1.000 - 2.000i
.000 + 2.000i   .000 - 2.000i

6.2 Precision variants

The types int, real, compl and bits come in several sizes. The prefix long gives a variant with more bits, long long one with still more, and short and short short variants with fewer. How many variants there are and how large they are depends on the implementation. A variant that the implementation does not distinguish has the same values as the next larger or smaller one, but it is still a type of its own: a long long int must be converted with SHORTEN to become a long int, even where both have 64 bits.

Type ga68 a68j Algol 68 Genie
short short int 8 bits 8 bits 64 bits
short int 16 bits 16 bits 64 bits
int 32 bits 32 bits 64 bits
long int 64 bits 64 bits 128 bits
long long int 64 bits 64 bits 72 decimal digits
real 32 bits 32 bits 64 bits
long real 64 bits 64 bits 128 bits
long long real 80 bits 64 bits 63 decimal digits
bits 32 32 64
long bits 64 64 128

A literal of a long type is written with the prefix: long 1, long 2.5, long long 0. The operator LENG converts a value to the next longer type and SHORTEN to the next shorter one; there is no implicit conversion between the sizes, so a long int and an int cannot be added without LENG. The names of the standard constants and functions for the long types begin with long_: long_max_int, long_pi, long_sqrt.

long int big = long 123456789 * long 1000000;
print ((big, newline));
print ((long_max_int, newline));
long real third = long 1 / long 3;
print ((third, newline));
print ((LENG max_int + long 1, newline));       { no overflow in long }
print ((SHORTEN (long 2 ** 20), newline))
    +123456789000000
+9223372036854775807
+3.33333333333333e  -1
         +2147483648
   +1048576

The last two lines show the conversions: LENG max_int + long 1 computes in long int and so does not overflow, and SHORTEN converts a value that fits back to int.

The long types are what a program needs for exact large integers and for precise floating-point computations. With 32-bit integers, 13! already overflows; with long int, all factorials up to 20! are exact:

access Genie_Transput
begin
   { Factorials with long int, and their numbers of digits. }
   long int f := long 1;
   for n to 20 do
      f *:= LENG n;
      if n MOD 5 = 0 then
         string digits = whole (f, 0);
         print ((whole (n, -2), "! = ", whole (f, -20),
                 "  (", whole (UPB digits, 0), " digits)", newline))
      fi
   od
end
 5! =                  120  (3 digits)
10! =              3628800  (7 digits)
15! =        1307674368000  (13 digits)
20! =  2432902008176640000  (19 digits)

Implementation note.  Genie_Transput prints long int and long real values, but not the short and long long variants; they are converted with LENG or SHORTEN before printing. In Algol 68 Genie, long long int and long long real are computed in software with a very large precision, which Rosetta Code programs use for big numbers.

6.3 Bit sets

A value of type bits is a fixed-size sequence of bits, as many as the constant bits_width says. It is the Algol 68 equivalent of an unsigned integer used as a set of flags or a bit mask. Literals are written in base 2, 4, 8 or 16 with a prefix that gives the base: 2r1100, 8r14 and 16rc are the same value. The operators on bits are:

Operator Result
a AND b, a OR b, NOT a bitwise and, or, complement
a SHL n, a SHR n shift left or right by n bits
n ELEM a bit n of a, as a bool
a = b, a /= b equality
a <= b, a >= b subset, superset (not numerical order)
ABS a, BIN n conversion to and from int 
bits a = 2r1100, b = 16r0a;                  { 12 and 10 }
print ((ABS (a AND b), ABS (a OR b), ABS (a SHL 2), ABS (a SHR 2), newline));
print ((a, newline));
print ((bits_width, " ", bits_width ELEM a, (bits_width - 2) ELEM a, newline));
bits c = BIN 37;                             { from int to bits }
print ((ABS c, " ", ABS bits_pack ((true, true, false)), newline))
         +8        +14        +48         +3
FFFFFFFFFFFFFFFFFFFFFFFFFFFFTTFF
        +32 FT
        +37          +6

Two details differ from current conventions. First, print writes a bits value as a row of T and F characters, one per bit. Second, the bits are numbered from the left: bit 1 is the most significant bit and bit bits_width the least significant one. In 2r1100, the two set bits are therefore numbers 29 and 30 of 32. The function bits_pack builds a bits value from an array of bool, whose last element becomes the least significant bit.

Pitfall.  The comparisons of bits values are set comparisons: 2r100 >= 2r011 is false, since the first value does not contain the bits of the second. For numerical order, compare ABS a and ABS b. ELEM has the precedence 7, so i + 1 ELEM b means i + (1 ELEM b) and is rejected; write (i + 1) ELEM b. A negative shift count shifts in the other direction. And ABS of a value whose first bit is set does not fit into an int of the same width: the Report leaves the result undefined, and a68j gives a negative number.

Implementation note.  ga68, a68j and Algol 68 Genie also provide XOR for bits, which the Report does not have; it can be written as (a OR b) AND NOT (a AND b).

6.4 Byte strings

The type bytes is a string of fixed length, bytes_width characters, stored compactly. It was meant for machines on which a string was expensive. The function bytes_pack converts a string to bytes, and n ELEM b selects a character.

bytes code = bytes_pack ("ALGOL");
print ((2 ELEM code, " ", 5 ELEM code, newline))
L L

Implementation note.  ga68 and a68j do not yet support bytes; the example was run with Algol 68 Genie. Programs rarely need this type today, since string serves the same purpose.

6.5 Environment enquiries

The standard library contains constants that describe the implementation, which the Report calls environment enquiries. A program that wants to be portable uses them instead of assuming particular sizes:

print (("max_int        ", max_int, newline));
print (("long_max_int   ", long_max_int, newline));
print (("small_real     ", small_real, newline));
print (("long_small_real", long_small_real, newline));
print (("bits_width     ", bits_width, newline));
print (("int_lengths    ", int_lengths, newline));
print (("int_shorths    ", int_shorths, newline))
max_int        +2147483647
long_max_int   +9223372036854775807
small_real     +1.192093e -7
long_small_real+2.22044604925031e -16
bits_width             +32
int_lengths             +2
int_shorths             +3

The most important ones are:

Constant Meaning
max_int, long_max_int the largest integer of each size
max_real, long_max_real the largest real of each size
small_real the smallest real x with 1 + x > 1 and 1 − x < 1
int_lengths, int_shorths 1 + the number of long, short sizes of int
real_lengths, real_shorths the same for real
bits_width, bytes_width the number of bits in bits, characters in bytes
int_width, real_width the digits needed to print an int, a real
max_abs_char the largest character code
blank, null_character the space character, a filler character (code 0 here)
flip, flop the characters for true and false ("T" and "F" here)

int_lengths and int_shorths count int itself, so int_lengths = 2 means that there is one distinct long size (and int_shorths = 2 one short size); a larger prefix gives a type with the same values as the largest distinct one.

6.6 Mathematical functions

The standard library provides the mathematical functions of Section 5.6, each also in a version for each long size: sqrt, exp, ln, sin, cos, tan, arcsin, arccos, arctan; for long real, they are long_sqrt, long_exp, and so on. The function random returns a pseudo-random real between 0 and 1.

for i from 0 to 3 do
   real x = i * pi / 8;
   print ((fixed (x, -6, 4), fixed (sin (x), -8, 4), fixed (cos (x), -8, 4),
           fixed (exp (x), -8, 4), newline))
od;
print ((fixed (long_sqrt (long 2), 0, 15), newline))
0.0000  0.0000  1.0000  1.0000
0.3927  0.3827  0.9239  1.4810
0.7854  0.7071  0.7071  2.1933
1.1781  0.9239  0.3827  3.2482
1.414213562373095

The negative widths ask fixed for a field of six or eight characters without a plus sign (Section 2.14).

6.7 Extending the standard operators

A program can declare a standard operator for operand types that the library does not cover, as Chapter 5 did for fractions. The standard MOD, for example, is defined for integers only; a declaration adds a version for real operands, while the standard MOD keeps its meaning:

op MOD = (real a, b) real: a - b * ENTIER (a / b);
print ((fixed (7.5 MOD 2.0, 0, 2), " ", fixed (-7.5 MOD 2.0, 0, 2), newline));
print ((7 MOD 2, newline))                   { the standard MOD }
1.50 .50
         +1

Exercises

The answers are at the end of the book.

  1. What are RE ((1 I 1) * (1 I -1)) and ABS (0 I 2)?

  2. Why is long int n := 5 not allowed, and how is it written correctly?

  3. Assuming bits_width is 32, what are ABS (16rff AND 2r1010), ABS (2r1 SHL 4) and 32 ELEM 2r1?

  4. Write a function popcount that counts the set bits in a bits value, using ELEM.

  5. How can a program find out whether long long int is longer than long int in the implementation it runs on?

  6. Is 2r100 >= 2r011 true? Why or why not?

  7. What does 2 * 3 I 4 mean?

Programming problems

  1. Compute 262 and 339 exactly with long int.

  2. Print the first 90 Fibonacci numbers with long int.

  3. Use the Newton iteration z ← z − (z3−1)/(3z2) to find which of the three cube roots of 1 is reached from each starting point of a grid in the complex plane, and print the grid as characters.

  4. Represent a set of the numbers 1 to 32 as bits, and write the operations union, intersection, membership and size.

  5. Mandelbrot. Print the Mandelbrot set with characters, using compl arithmetic.

  6. A bit sieve. Write the sieve of Eratosthenes on an array of bits words, splitting a number into a word index and a bit number, and compare its size with the [] bool version of Chapter 4.

  7. Gray code. Convert numbers to their Gray code (n XOR (n SHR 1) on bits) and back, and print the codes of 0 to 15.

  8. An adder. Add two positive numbers given as bits bit by bit, as hardware does, with a carry, and report an overflow.

  9. Machine epsilon. Find the smallest power of 2 that, added to 1, gives a result different from 1, by halving, for real and long real, and compare it with small_real.

  10. Exact factorials. Compute 50! exactly with an array of int digits in base 10000, and compare the result with long long int in Algol 68 Genie.

  11. Safe fractions. Make the rational numbers of Chapter 5 safe from overflow: compute the products in long int with LENG, reduce with a long greatest common divisor, and convert back with SHORTEN only after checking against LENG max_int. Use them for the first terms of a power series with exact coefficients, such as that of ex.
