Appendix F: Calling C

A program sometimes needs a function that exists only in another language: a routine of the C library, of the operating system, or of a library written in C. ga68 can call such functions directly, and it can also use variables of a C program. This appendix describes how. The mechanism is a GNU extension; a68j and Algol 68 Genie cannot call C (a68j has a similar mechanism for Java methods, described in its own documentation).

Formal holes

The construct that names a C function or variable is a formal hole:

nest C "name"

It is written where a value is expected and stands for that value. Its type is not written in the hole; it is the type the context requires, so a formal hole may only be written in a strong context (Section 7.14), such as the value of a constant declaration, an argument or the right-hand side of an assignment:

proc (int) int c_abs = nest C "abs";
proc (long real) long real cbrt = nest C "cbrt";
proc (real) real cbrtf = nest C "cbrtf";
print ((c_abs (-7), newline));
print ((fixed (cbrt (long 2.0), 0, 12), newline));
print ((fixed (cbrtf (2.0), 0, 12), newline))
         +7
1.259921049895
1.259921073913

Each declaration says which type the C function has in Algol 68 terms. The compiler translates the type into the corresponding C type and generates a call of the C function with that name. The name C after nest is the language; the word C is not reserved and can still name a type, an operator or a module elsewhere in the program. The C library and the mathematical library are linked with every program by the ga68 command, so their functions need nothing else.

The notation goes back to the proposal for modules and separate compilation of 1978 [7] (the same proposal as the modules of Appendix E). There, a formal hole marks a place in one part of a program that another, separately compiled part fills in, so that a program can be developed top-down; the proposal already allowed the part to be written in another language, with an example in Fortran. ga68 provides only the second use.

Types

The types that can cross the border are the simple ones and those built from them:

Algol 68 C
void (as a result) void
bool bool
char a 32-bit integer (the character code)
int, short int, short short int int, short, char
long int, long long int long, long long
bits, short bits, short short bits unsigned int, unsigned short, unsigned char
long bits, long long bits unsigned long, unsigned long long
real, long real float, double
ref T a pointer to T
proc with parameters and result of these types a function, or a pointer to one
a record with fields of these types the corresponding struct
string, only as a parameter three parameters, see below

Other arrays and unions cannot be passed.

Pitfall.  Nothing checks that the declared type matches the C function. The compiler trusts the declaration, and the C library has no type information to compare it with. A wrong type gives wrong results, not an error message. The most likely mistake is the floating-point type: since real is a C float, a function of the C library that takes and returns double, such as cbrt or sin, must be declared with long real, as in the example above; declared with real, it receives and returns meaningless bit patterns. The float variants have an f at the end of their name (cbrtf).

Variables

A C variable can be used in two ways. Without further marking, the hole stands for the value of the variable at the moment the hole is evaluated, here when the declaration is executed; later changes by the C program are not seen:

int limit = nest C "limit";

With an ampersand before the name, it stands for the variable itself, and the Algol 68 declaration has a reference type: assignments to it change the C variable, and the C program sees them.

ref int calls = nest C "&calls";

Without the ampersand, a hole of a ref type stands for the value of a C pointer variable, so the Algol 68 name refers to the C object the pointer points to.

Strings and functions as parameters

A C function that receives an Algol 68 string gets three parameters for it: a pointer to the characters, the number of characters, and the distance in bytes from one character to the next. The characters are 32-bit codes, not bytes, and they need not be next to each other, because the string may be a column of a two-dimensional array of characters, such as m[, 2]. A C function that counts the vowels of a string, a C function that calls a function it receives, and a counter variable:

/* C side of the example cfun.a68. */
#include <stddef.h>
#include <stdint.h>

int calls = 0;

/* The number of vowels in an Algol 68 string: the characters (UCS-4),
   their number and the distance in bytes between two of them. */
int vowels (const uint32_t *s, size_t len, size_t stride)
{
  int n = 0;
  calls++;
  for (size_t i = 0; i < len; i++)
    {
      uint32_t c = *(const uint32_t *) ((const char *) s + i * stride);
      if (c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u')
        n++;
    }
  return n;
}

/* Calls f for 1, ..., n and returns the sum of the results. */
int sum_of (int (*f) (int), int n)
{
  int s = 0;
  calls++;
  for (int i = 1; i <= n; i++)
    s += f (i);
  return s;
}

and the Algol 68 program that uses them:

ref int calls = nest C "&calls";
proc (string) int vowels = nest C "vowels";
proc (proc (int) int, int) int sum_of = nest C "sum_of";

string s = "parametrization";
print ((vowels (s), " ", vowels (s[1:5]), newline));
proc square = (int i) int: i * i;
print ((sum_of (square, 4), newline));
print (("calls: ", calls, newline))
         +7          +2
        +30
calls:          +3

The C file is compiled with a C compiler and linked with the program:

$ cc -c cfun.c
$ ga68 -I. cfun.a68 cfun.o genietransput.o -o cfun

An Algol 68 function that is passed to C, such as square above, arrives as an ordinary C function pointer. ga68 makes it point to a small piece of code that it places in the stack frame of the block in which the function is declared. A C library must therefore not keep the pointer and call it after that block has ended, even if the function uses no names of the block. The same piece of code is the reason why the linker warns that such a program “requires executable stack”; the warning is expected, but a system that forbids executable stacks will not run the program.
