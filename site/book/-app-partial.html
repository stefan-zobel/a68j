Appendix G: Partial parametrization

Section 7.16 showed that an Algol 68 function cannot be returned from the block whose names it uses: a function that composes two other functions, the everyday closure of current languages, is an error. Soon after the Revised Report, Lindsey proposed an extension that removes most of this limitation without changing the lifetime rule [6]. The subcommittee of IFIP Working Group 2.1 that looked after Algol 68 released it in 1976, so that implementations that experimented with such a facility would all provide it in the same form; it is not part of the Revised Report. Algol 68 Genie implements it; ga68 and a68j do not (Appendix C): a68j rejects such a call with a message, and ga68 currently stops with an internal compiler error. The programs of this appendix were run with Algol 68 Genie.

Leaving arguments out

With partial parametrization, a call may leave arguments out, by writing nothing in their places; the commas stay. Such a call does not run the function; it yields a new function that takes the missing arguments and has the given ones stored inside it:

proc add = (real x, y) real: x + y;
proc (real) real add3 = add (3, );
print ((fixed (add3 (4), 0, 1), " ", fixed (add (3, ) (10), 0, 1), newline))
7.0 13.0

add (3, ) is a function of one real, which adds 3. It can be called at once, as in add (3, ) (10), or kept and called later. The functional languages call the same idea partial application; in Python it is functools.partial, in C++ std::bind.

A function can be given its arguments in several stages. Each stage stores the new arguments and yields a function of the remaining ones:

proc volume = (real l, w, h) real: l * w * h;
proc (real, real) real base2 = volume (2, , );
proc (real) real base6 = base2 (3, );
print ((fixed (base6 (4), 0, 1), " ", fixed (base2 (1, 1), 0, 1), newline))
24.0 2.0

Closures without the lifetime problem

The stored arguments are part of the new function: they are copied into it, and the function does not refer to the block in which the call was made. This is what makes the idea work. Instead of using the names of an enclosing block, the inner function receives everything as parameters, and the outer function supplies them by partial parametrization. The function compose of Section 7.16, which Algol 68 Genie stops at run time there, becomes:

mode Fn = proc (real) real;
proc compose = (Fn f, g) Fn: ((Fn f, g, real x) real: f (g (x))) (f, g, );
proc double = (real x) real: 2 * x;
proc inc = (real x) real: x + 1;
Fn h = compose (double, inc);
print ((fixed (h (1), 0, 1), newline))
4.0

The inner function uses only its own parameters f, g and x. compose gives it the first two and returns the result, which no longer depends on compose’s parameters. Lindsey’s proposal shows the same pattern with an operator that raises the value of a function to a power, so that the cosine “squared” yields cos2θ. The operator ^ below instead applies a function n times:

mode Fn = proc (real) real;
proc iterate = (Fn f, int n, real x) real:
begin
   real y := x;
   to n do y := f (y) od;
   y
end;
prio ^ = 8;
op ^ = (Fn f, int n) Fn: iterate (f, n, );
proc half = (real x) real: x / 2;
print ((fixed ((half ^ 3) (1), 0, 3), " ", fixed ((cos ^ 20) (1), 0, 6), newline))
.125 .739184

Twenty applications of cos to 1 come close to the number x with cos x = x, 0.739085…; more applications get closer.

When the arguments are evaluated

The arguments of a call that leaves arguments out are evaluated when the call is made, not when the resulting function is finally called. A value is stored as it is at that moment; a reference is stored as a reference, so the function sees later changes of the variable it refers to:

proc add = (int a, b) int: a + b;
proc incr = (ref int c, int d) int: c +:= d;
int n := 1;
proc (int) int add_n = add (n, );
ref int counter = heap int := 0;
proc (int) int bump = incr (counter, );
n := 10;
print ((add_n (5), newline));
bump (1); bump (2);
counter +:= 100;
print ((bump (3), newline))
                  +6
                +106

add_n keeps the value 1 that n had when add_n was made; the later assignment to n does not change it. bump keeps the reference counter, and every call increases the same cell. A heap cell and a function that keeps a reference to it are the counter of Section 7.16 without the need to pass the counter along.

Pitfall.  The lifetime rule still applies to what is stored. A function made by partial parametrization lives only as long as both the original function and every value stored in it, whichever ends first. If a stored reference refers to a loc cell of a block, the function must not outlive that block:

proc incr = (ref int c, int d) int: c +:= d;
proc make_bump = proc (int) int:
begin
   loc int count := 0;
   incr (count, )
end;
proc (int) int bump = make_bump;
print ((bump (1), newline))
3        PROC incr = (REF INT c, INT d) INT: c +:= d;
                                             1       
a68g: runtime error: 1: REF INT value is exported out of its scope, in VOID closed-clause starting at "BEGIN" in line 1.

The cell count ends with the block of make_bump, and the function returned holds a reference to it. By the rules of the proposal, returning the function from the block is the error. Algol 68 Genie does not check it there; it stops the program only when the function is used, here in incr, whose result is the cell that no longer exists. The counter must be a heap cell, as in the previous example.

Calls with all arguments

In Lindsey’s proposal, every call is a partial parametrization: a call that supplies all arguments yields a function without parameters, which is then called at once if the context requires a value, the usual case. If the context requires a function without parameters, the call is not executed but kept: proc int tick = incr (counter, 1) would declare a function that increases counter by 1 each time it is called.

Implementation note.  Algol 68 Genie does not implement this part of the proposal. It runs a call as soon as all arguments are given, and rejects the declaration of tick:

5        PROC INT tick = incr (counter, 1);
                         1                 
a68g: error: 1: INT cannot be coerced to PROC INT in a strong-unit, in closed-clause starting at "BEGIN" in line 1.

Leaving out at least one argument, as bump does above, works in Algol 68 Genie.
