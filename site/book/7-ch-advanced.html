7 Advanced types

The types of the previous chapters were built in simple ways: arrays of numbers, records of strings and numbers, functions of numbers. This chapter shows the full power of the type system. It introduces arrays that change their size, unions of types, references to references, and recursive types such as lists and trees, and it combines them in larger examples. It then collects the rules that earlier chapters introduced piece by piece: all implicit conversions and the places where each is allowed, and the rules that govern how long a value lives.

This is the chapter where Algol 68 differs most from the languages that most programmers know. Many of its rules are easy to state and have consequences that are not obvious, so the chapter shows those consequences, including the ones that the compilers do not report.

The guiding principle behind all of it is orthogonality (Section 7.13): every way of building a type can be applied to every type, and every construct works the same way whatever the types involved.

7.1 Resizable arrays

The arrays of Chapter 4 have fixed bounds. A variable declared with flex before the bounds can hold arrays of any size; each assignment gives it the bounds of the assigned array:

flex [1:0] int list;                       { empty at first }
print ((UPB list, newline));
list := (3, 1, 4);
print ((UPB list, ":", list, newline));
list := list[2:3];                         { shrinks to two elements }
print ((UPB list, ":", list, newline));
[] int snapshot = list;                    { a fixed copy }
list := (1, 5, 9, 2, 6);
print ((UPB snapshot, UPB list, newline))
         +0
         +3:         +3         +1         +4
         +2:         +1         +4
         +2         +5

flex [1:0] int list declares a variable that holds an array of int, initially empty. The bounds in the declaration only determine the initial array. The Report calls such a variable a flexible name.

The value of a resizable array is an ordinary array: snapshot is a copy with the bounds 1 to 2, which does not change when list changes. The type of such a value is the array type without flex; the Report says that the type deflexes to it.

There is no operation that adds an element to a resizable array in place. An array literal cannot help either: each element of the literal must be an int, and squares is an array, so the compiler rejects (squares, i * i):

flex [1:0] int squares;
for i to 6 do
   squares := (squares, i * i)    { not allowed: see the text }
od
append.a68:6:7: error: ref flex [] int cannot be coerced to 'int' in a strong-unit

Instead, a new, longer array is built and assigned. A procedure does this once and for all:

proc append = (ref flex [] int list, int value) void:
begin
   [1 : UPB list + 1] int longer;
   longer[: UPB list] := list;
   longer[UPB list + 1] := value;
   list := longer
end;
flex [1:0] int squares;
for i to 6 do append (squares, i * i) od;
print ((squares, newline))
         +1         +4         +9        +16        +25        +36

The parameter has the type ref flex [] int: a reference to a resizable array variable, the only kind of variable whose bounds may change. A ref [] int parameter would accept fixed arrays as well, and could therefore not be given a longer array. In the Report, the two are even different types: a ref flex [] int cannot be passed as a ref [] int. This is the price of Algol 68’s value semantics for arrays: what other languages call a dynamic array or list (std::vector, ArrayList, a Python list) is here written out explicitly.

Implementation note.  ga68, a68j and Algol 68 Genie accept a ref flex [] int argument for a ref [] int parameter, contrary to the Report. A program that relies on this is not portable.

7.2 Where flex can stand

flex is a property of variables, not of values: an array value always has fixed bounds, and only a variable can be given a new array of a different size. flex therefore belongs in the type of a variable, that is, under a ref. It can appear in a variable declaration, as above, in the type ref flex [] int of a parameter, and in a type declaration that is used to declare variables:

mode Buffer = flex [1:0] int;
Buffer b := (1, 2, 3);
b := (4, 5)

The standard type string is exactly such a declaration (Section 7.4). A type declaration needs bounds, even if they are only initial ones: mode B = flex [] int is rejected with “actual bounds expected”. A constant cannot be resizable, so flex [] int b = (1, 2, 3) is not allowed by the Report; the implementations accept it and treat b as a [] int.

Deflexing also applies to the fields of a record. A variable of type struct (string name, int age) holds records whose name can have any length, but the record value that the variable holds has a field of type [] char, with the bounds of its current name.

Jagged arrays

A two-dimensional array [,] int is rectangular: all its rows have the same length. An array of arrays, [] [] int, is a different type, whose elements are arrays in their own right and may have different lengths, like a Java int[][]. With flex at both levels, both the number of rows and each row can change:

[] [] int jag = ((1, 2), 3, (4, 5, 6));
for i to UPB jag do
   print ((whole (UPB jag[i], 0), " elements:"));
   for j to UPB jag[i] do print ((" ", whole (jag[i][j], 0))) od;
   print (newline)
od;
flex [1:0] flex [1:0] int rag := ((1, 2), 3, (4, 5, 6));
rag[2] := (7, 8, 9, 10);       { one row gets longer }
rag := rag[1:2];               { the array loses its last row }
print ((whole (UPB rag, 0), " rows, row 2 has ",
        whole (UPB rag[2], 0), " elements", newline))
2 elements: 1 2
1 elements: 3
3 elements: 4 5 6
2 rows, row 2 has 4 elements

In the literal ((1, 2), 3, (4, 5, 6)), the element 3 is converted to an array with one element (rowing, Section 4.10). The assignment to rag[2] gives the second row a new length, and rag := rag[1:2] drops the last row. In between lie the type [3] flex [1:0] int, three rows of which each can change, and flex [1:0] [3] int, a varying number of rows of fixed length 3.

Implementation note.  ga68 stops with an internal compiler error when a value of type [] [] int that is not a literal is assigned to a variable of type flex [] flex [] int, as in rag := jag. Assigning a literal, as in the example, works.

7.3 Growing an array efficiently

The procedure append of Section 7.1 copies the whole array each time it adds an element. Building an array of n elements this way copies about n2/2 elements, which is slow for large n. The dynamic arrays of other languages avoid this by keeping some spare room: the array is larger than the number of elements in use, and when it is full, it is replaced by one twice as large. Each element is then copied only a few times on average.

In Algol 68 the same structure is a record with a resizable array and a count:

mode Vector = struct (flex [1:0] int data, int size);
proc push = (ref Vector v, int x) void:
begin
   if size of v = UPB data of v then
      { full: move the elements into an array twice as large }
      [(UPB data of v = 0 | 4 | 2 * UPB data of v)] int bigger;
      bigger[1 : size of v] := (data of v)[1 : size of v];
      data of v := bigger
   fi;
   (data of v)[size of v +:= 1] := x
end;
Vector v := ((), 0);
for i to 10 do
   push (v, i * i);
   print ((whole (size of v, 3), whole (UPB data of v, 4), newline))
od

The program prints the number of elements and the capacity after each push:

 +1  +4
 +2  +4
 +3  +4
 +4  +4
 +5  +8
 +6  +8
 +7  +8
 +8  +8
 +9 +16
+10 +16

The field data of a Vector variable is itself a resizable array variable: if v has the type ref Vector, then data of v has the type ref flex [] int and can be assigned to, indexed, or passed to append of Section 7.1. The parentheses in (data of v)[i] are needed because indexing binds more tightly than selection (Section 4.9).

The same cost applies to strings: s +:= c in a loop builds a new string each time. For long texts, collecting the characters in a buffer of this kind and converting them at the end is much faster.

7.4 Strings

The type string is defined in the standard library as flex [1:0] char, a resizable array of characters. That is why a string variable can hold strings of any length. The library adds a few operators:

string s := "Algol";
s +:= " 68";                       { append }
"The " +=: s;                      { prepend }
print ((s, ", length ", whole (UPB s, 0), newline));
print ((3 * "ab", " ", "-" * 10, newline));
string letters := "";
for i to 5 do letters +:= REPR (ABS "a" + i - 1) od;
print ((letters, " ", "abc" < "abd", " ", "abc" = "ab" + "c", newline))
The Algol 68, length 12
ababab ----------
abcde T T

+ joins strings and characters; s +:= t appends t to s, and t +=: s puts t in front of s. * repeats a string a given number of times, and s *:= n replaces s by n copies of itself. The comparisons =, /=, <, <=, >, >= compare strings in dictionary order, by the codes of their characters. They are defined for [] char, so they apply to every array of characters, not only to string variables.

7.5 References into resizable arrays

An element of an array variable is itself a variable: a[1] is a reference to the first element. For a resizable array, such a reference must not be kept, since the next assignment to the array may give it a different size and place the elements elsewhere; the reference would then refer to a cell that no longer belongs to the array. The language therefore forbids binding such a reference to a name or storing it:

access Genie_Transput
begin
   flex [1:3] int a := (1, 2, 3);
   ref int first = a[1];
   first := 10;
   print ((a, newline))
end
transient.a68:4:20: error: attempt at storing a transient name

The Report calls a reference into a resizable array a transient name. The same problem is known in C++ as iterator invalidation; Algol 68 rules it out at compile time.

The rule is stricter than it looks. A transient reference may be used only directly, for an assignment or to obtain its value. It may not be bound to a name, stored, returned, or passed to a procedure or an operator, since a parameter is bound like a constant declaration and no type can be written for a transient reference. That excludes some everyday code:

flex [1:10] int count;
for i to 10 do count[i] := 0 od;
count[3] +:= 1
transient-count.a68:6:4: error: attempt at storing a transient name

+:= is an operator whose left operand is a reference, so count[3] +:= 1 passes a transient reference to it. For the same reason read (count[3]) and swap (count[i], count[j]) are rejected, and so is s[i] +:= "x" for an element of a flex [] string. Note that string is a resizable array, so the rule applies to the characters of every string variable. Selecting a field across all elements, x of path for a flex [] Point variable path, gives a transient reference as well.

There are three ways around it. The plain assignment count[3] := count[3] + 1 is allowed. If the size is known once the array has been filled, a fixed array can take over: [UPB count] int c := count is an ordinary array whose elements may be passed anywhere. And the restriction applies only to resizable arrays: the elements of fixed arrays and the fields of records are ordinary variables.

7.6 Sharing arrays

Arrays are values in Algol 68: assigning an array copies its elements (Section 4.3). An array is shared only when a reference to it is shared explicitly, which the type always shows:

[5] int a := (1, 2, 3, 4, 5);
ref [] int r = a;            { another name for a }
ref [] int s := a[2:3];      { a pointer to a slice of a }
r[1] := 10;
s[1] := 20;
int x := 7;
ref [] int one = x;          { x seen as an array of one element }
one[1] := 8;
print ((a, newline, x, newline))

prints

        +10        +20         +3         +4         +5
         +8

r is a constant of type ref [] int bound to the variable a: another name for the same array, so r[1] := 10 changes a. s is a variable that holds a reference to a part of a; s[1] is a[2]. And one shows the rowing of a variable: the reference x becomes a reference to an array with one element, which is x itself.

The same distinction exists for single values. ref int r = x makes r another name for x, like a reference int& r = x in C++. ref int p := x creates a variable that holds a reference to x and can later refer to something else, like a pointer int* p = &x in C. In Java and Python, objects and lists are always shared and a copy must be made explicitly; in Algol 68, as in C++ (and, with moves instead of copies, in Rust), values are copied and sharing must be made explicit.

7.7 Unions

A union type holds a value of one of several types, together with an indication of which type it is. union (int, real, string) holds an int, a real or a string. A value of any of these types can be assigned to a union variable or passed as a union parameter; this implicit conversion is uniting (uniting).

To use the value inside a union, the program must find out its type. This is done with a special form of case, which the Report calls a conformity clause:

mode Value = union (int, real, string);
proc describe = (Value v) string:
   case v in
      (int n):    "the int " + whole (n, 0),
      (real x):   "the real " + fixed (x, 0, 2),
      (string s): "the string """ + s + """"
   esac;
[] Value items = (42, 2.5, "hello");
for i to UPB items do print ((describe (items[i]), newline)) od;
Value v := 7;
v := "seven";                          { now it holds a string }
print ((describe (v), newline))
the int 42
the real 2.50
the string "hello"
the string "seven"

Each alternative names a type and, optionally, a name for the value: (int n): ... is chosen if the union holds an int, and binds n to it. An out part handles the types that no alternative names. A union without a name in its alternative only tests the type:

union (int, string) u := "text";
bool is_int = case u in (int): true out false esac;
print ((is_int, newline));
u := 5;
case u in
   (int n): print ((n * 2, newline))
out
   print (("not an int", newline))
esac
F
        +10

The union is a tagged union, or sum type: the type of the current value is recorded with it and checked at run time, so a value can never be read as the wrong type. It corresponds to the enum of Rust and Swift, the variant types of ML and Haskell and std::variant of C++, and the conformity clause corresponds to their pattern matching. Unlike those, an Algol 68 union has no names for its alternatives; the alternatives are distinguished by their types only. Two alternatives that carry the same type of value must therefore be wrapped in different record types.

The order of the types in a union does not matter, and a union that contains a union contains the members of the inner one: union (int, real) and union (real, int) are the same type, and union (int, union (real, string)) is union (int, real, string). A union value can be converted implicitly to a larger union, but not to a smaller one, since the value might be of a type that the smaller union lacks.

The types of a union must be clearly distinct: union (int, ref int) is rejected (“firmly related components”), because an int variable could become either member. A union value needs the space of its largest member plus the tag, and every conformity clause is a test at run time.

The print procedure is an example of unions at work: its parameter is an array of a union of all the types it can print.

7.8 Working with unions

What a conformity clause binds

The name in an alternative is a constant that holds a copy of the value: in (int n): n +:= 1 the compiler rejects the assignment. To change the value in a union variable u, assign a new value to u itself, as in (int n): u := n + 1. An alternative may also name a union of some of the members: (union (int, real) x): ... is chosen for an int or a real, and x is then a value of that smaller union.

The alternatives are chosen by the exact type of the value, without conversions. An int in a union does not match an alternative for real:

union (int, real) u := 3;
case u in
   (real r): print (("real ", fixed (r, 0, 1), newline))
   out print (("not a real", newline))
esac
not a real

Pitfall.  A conformity clause without an out part, none of whose alternatives matches, does nothing and yields an undefined value. There is no error at compile time or at run time:

union (int, real, string) u := "seven";
int n = case u in (int i): i, (real r): ROUND r esac

ga68 and a68j give n the value 0, Algol 68 Genie the value 1. Rust rejects a match that does not cover every case, and a Haskell compiler warns about it and the program stops at run time; Algol 68 does neither. Every conformity clause that is not meant to ignore the remaining types should have an out part that reports the error.

Optional values

A union with void is the Algol 68 form of an optional value, the Option<T> of Rust or the Optional<T> of Java. The only value of type void is written empty:

mode Maybe = union (int, void);
proc find = ([] int a, int x) Maybe:
begin
   Maybe result := empty;
   for i from LWB a to UPB a while (result | (void): true | false) do
      if a[i] = x then result := i fi
   od;
   result
end;
[] int primes = (2, 3, 5, 7, 11);
for x from 4 to 7 do
   case find (primes, x) in
      (int i): print ((whole (x, 0), " at ", whole (i, 0), newline)),
      (void): print ((whole (x, 0), " not found", newline))
   esac
od
4 not found
5 at 3
6 not found
7 at 4

nil serves the same purpose for references, but only for them; a search that returns an index needs union (int, void). The while part of the loop uses the short form of the conformity clause: (result (void): true | false)| is case result in (void): true out false esac. Rosetta Code programs use the short form often.

Which values can be united

Implicit conversions happen in a fixed order (Section 7.14): uniting and widening are alternatives, and rowing can only follow them. A value is therefore united only if its own type is a member of the union, not a type that it could be widened or rowed to:

union (real, string) u := 1;
skip
union-order.a68:4:25: error: int cannot be coerced to union (real, string) in a strong-unit
union (int, string) u := "x";
skip
union-char.a68:4:24: error: char cannot be coerced to union (int, string) in a strong-unit

1 is an int, not a real, and "x" is a char, not a string; neither is a member of the union. The remedies are to write the value with the right type (1.0) or to annotate it (real (1), string ("x"), Section 7.12). For the same reason, print (1) prints an integer: int is a member of the union that print accepts, so it is not widened. A one-character string literal must be annotated when it is to become a string in a union; this is a common surprise.

A record literal has no type of its own, so it cannot be united either: with mode Pt = struct (int x, y), Sz = struct (int w, h), the declaration union (Pt, Sz) r := (1, 2) is rejected, and union (Pt, Sz) r := Pt (1, 2) says which member is meant. Uniting does not reach through a reference: a function with a parameter of type ref union (int, real) does not accept an int variable; the caller must pass a variable of the union type. Nor can a union whose members are arrays be indexed directly: a conformity clause must first say which member it holds. And no conversion applies to the elements of an array: a [] int is never converted to a [] real or to an array of a union. (Java allows an Integer[] to be used as an Object[], which is why Java must check every store into an array at run time.)

7.9 References to references

A reference is a value, so there are variables that hold references. A variable of type ref int is declared like any other variable, and its type is ref ref int. Such a variable is what C calls a pointer:

int a := 1, b := 2;
ref int p := a;          { p holds a reference to a }
p := b;                  { now p refers to b; a and b are unchanged }
ref int (p) := 20;       { assigns to what p refers to, that is to b }
print ((a, b, newline));
print ((p is b, " ", p isnt a, newline))
         +1        +20
T T

The assignment p := b stores the reference b in p; it does not change a or b. Which cell an assignment changes is determined by the type of its left-hand side: the left-hand side of p := b is p itself, of type ref ref int, so a ref int is stored. To assign to the cell that p refers to, the left-hand side must be the ref int that p holds. The expression ref int (p) says exactly that: it is p converted to the type ref int, which dereferences it once.

The null reference is written nil; it refers to no cell, and any attempt to use it as a variable is an error. Two references are compared with is and isnt (also written :=: and :/=:); the Report calls these identity relations. They compare references, not the values in the cells: p is b is true because p refers to the same cell as b.

Comparing a pointer with nil needs care. In an identity relation, one side is in a soft context, where no dereferencing happens, and the other in a strong one, in either order. nil can only stand in a strong context, so in q is nil the variable q is the soft side and is not dereferenced at all: the comparison is between the variable q itself and nil, which is always false. The test for a null pointer is ref int (q) is nil:

ref int q := nil;
print ((q is nil, " ", ref int (q) is nil, newline))
F T

This is the most common pitfall of Algol 68 references, and a direct consequence of the rule that an implicit conversion never happens unless the context requires it.

7.10 Comparing references

The same rule applies to two pointer variables. If p and q are both of type ref ref int and both refer to n, then p is q compares the two variables themselves, which are different cells:

int n := 1;
ref int p := n, q := n;
print ((p is q, " ", ref int (p) is ref int (q), " ", ref int (p) is n, newline))
F T T

prints F T T. The question that is usually meant, whether the two pointers refer to the same cell, is ref int (p) is ref int (q). The rule of thumb: annotate one side with the type of the references that are to be compared, and the other side is dereferenced to the same type. ref int (p) is n compares the reference held by p with the variable n.

An identity relation is not an operator. It cannot be redefined, and it binds more loosely than every operator, so it must be put in parentheses when it is combined with AND, OR, andth or orel: p is q AND b means p is (q AND b) and is rejected, and the condition of a loop over a list is written while (ref Node (p) isnt no_node) andth value of p /= v do.

7.11 Records with reference fields

A record field can be a reference, and a constant record can then contain something that changes. A gas meter has a fixed serial number and a reading that grows:

mode Meter = struct (int serial, ref int reading);
Meter m = (23146, heap int := 0);
reading of m := 10;          { m is a constant, its reading is not }
Meter v := m;                { copies the reference, not the cell }
ref int (reading of v) := 30;
print ((whole (reading of m, 0), newline))
30

prints 30. m is a constant, but its field reading is a ref int, and the cell it refers to can be assigned to. Copying the record into v copies the reference, not the cell, so m and v share the reading. This is the behavior of a final field that refers to a mutable object in Java. The semaphores of Chapter 8 are records of this kind.

Assigning to the reading through the variable v needs an annotation. reading of v is a field of a variable, and therefore has the type ref ref int: the variable that holds the reference. reading of v := 30 would try to store an int in it. The annotation ref int (reading of v) dereferences once and yields the cell to be changed. In contrast, selecting from or indexing through a reference needs no annotation: if pa is a variable of type ref [] int, then pa[1] := 5 assigns to an element of the array it refers to, and next of p in the lists below selects from the record that p refers to. The Report calls this the weak dereferencing of Section 7.14.

7.12 Type annotations

An expression of the form Type (expression) is a cast. The word suggests a conversion as in C, but an Algol 68 cast converts nothing by force: it only places the expression in a strong context with the given target type, so that exactly the implicit conversions to that type happen. A cast is therefore a type annotation, like e: T in Rust or TypeScript. It cannot convert a real to an int; that needs ROUND or ENTIER.

union (int, real) u = real (1);           { a real, not an int }
print ((case u in (real): "real", (int): "int" esac, newline));
proc next = int: 42;
proc int saved = next;                    { the function itself }
int value = next;                         { the result of a call }
print ((saved, value, newline))
real
        +42        +42

The cast real (1) makes the united value a real rather than an int. The declaration proc int saved = next binds the function itself, since its type is a function type, whereas int value = next calls it.

An array or record literal is allowed only where the type it must have is known, that is, in a strong context. It cannot be the operand of an operator, where the operator is not yet known; an annotation provides the type:

print ((UPB [] int (1, 2, 3), newline))
         +3

UPB (1, 2, 3) would be rejected. Annotations are also the way to say which member of a union a record literal belongs to (Section 7.8), and void (x := f) discards a value explicitly.

7.13 Orthogonality

The constructions of types can be combined without restriction. There are arrays of functions ([] proc (real) real), functions that return functions (proc (int) proc (int) int), records with function fields, unions of records, references to arrays of references, and so on. Every type except void can be the type of a parameter, a result, a field or an element; void can be the result of a function and a member of a union.

The constructs of the language are equally orthogonal. Any expression can stand wherever a value of its type is required, and a block or an if can stand where other languages only allow a simple expression, as Chapter 3 showed. This is why Algol 68 needs few special rules, and why its few rules apply everywhere.

7.14 Implicit conversions and contexts

The chapters so far introduced the six implicit conversions one at a time. Here they are together:

Conversion Report Effect
dereferencing dereferencing a reference is replaced by the value it refers to
calling deproceduring a parameterless function is called
uniting uniting a value becomes a value of a union type
widening widening int to real to compl;
bits to [] bool; bytes to [] char
rowing rowing a value becomes an array with one element,
an array gains a dimension
discarding voiding a value is thrown away

Rowing also applies to references: a variable of type ref int can become a ref [] int whose only element is the variable itself (Section 7.6).

Where each conversion is allowed depends on the context in which the expression stands. There are five contexts, from the most to the least permissive:

Context Where Conversions allowed
strong right-hand side of a declaration or all
assignment, argument, cast, function
body, element of a literal, one
side of an identity relation
firm operand of an operator dereferencing, calling, uniting
meek condition of if, case, while; dereferencing, calling
index, bound, from, by, to;
the function in a call
weak the array in an indexing, the record dereferencing (but not of
in a selection the last reference), calling
soft left-hand side of an assignment, calling
one side of an identity relation

In a strong context, the required type is known, and the compiler applies whatever conversions lead to it, always in the same order: first dereferencing and calling as often as needed, then either one uniting or widening (twice for int to compl), then rowing (once per dimension added). A parameterless function f of type proc ref int that stands where a real is required is called, its result is dereferenced, and the int is widened.

In a firm context, the operator is not known until the types of the operands are, so the conversions that would change the type substantially (widening, rowing) are excluded; uniting is allowed so that an operator can be declared for a union. A meek context requires a value of a particular kind, such as a bool for a condition or an int for an index, and only dereferencing and calling are allowed. A weak context keeps a reference: in a[i] := 0, the array a is not dereferenced to its value, since the element must remain a reference to be assigned to; this is also why a slice of an array variable is a reference (Section 4.5). And a soft context keeps the reference on the left-hand side of an assignment entirely.

The branches of an if or a case that yields a value are balanced: one of them is in the context of the whole expression, and the others are in a strong context, so they can be converted to a common type even where the context itself allows little. if b then 1 else 2.5 fi is a real, and so is (b 1 | 2.5) + 1|. On the left-hand side of an assignment, if b then x else y fi := 0 needs branches that yield references of one type, though a branch may be dereferenced to match the other.

The Report calls a context a syntactic position and its kind its sort. Most of the time, these rules are invisible: they make x := x + 1 mean what it should. They become visible in error messages, which mention them (“in a strong-unit”), and in the cases of this chapter: the pointer comparisons, the order of uniting and widening, and the annotations that help in an ambiguous situation.

7.15 Lifetimes

Every value that a program creates exists for a certain time. A cell allocated by loc, which includes every variable declaration, lives as long as the block in which it is allocated is running; when the block ends, the cell is gone. A cell allocated by heap lives as long as the program can reach it; when no reference to it remains, its memory is reclaimed by a garbage collector. A function can therefore return a reference to a new heap cell:

proc counter = (int start) ref int: heap int := start;
ref int c = counter (10);
c +:= 5;
print ((c, newline))
        +15

The Report calls the lifetime of a value its scope, a word this book reserves for the visibility of names (Section 3.3). A block creates a lifetime that is newer, that is shorter, than the lifetime of the enclosing block; heap cells and the values of the standard library have the longest lifetime. The lifetime of a record or an array that contains references is that of its shortest-lived reference.

The lifetime rule says that a reference must never outlive the cell it refers to: a value may not be assigned to a variable that lives longer than the value. Storing a reference to a local cell in a variable of an enclosing block, or returning it from the block, breaks the rule:

ref int p;
begin
   int x := 1;
   p := x          { wrong: p outlives x }
end

Rust enforces a rule of the same kind with its borrow checker, entirely at compile time; in Algol 68 it can only partly be checked by the compiler and otherwise must be checked while the program runs.

Implementation note.  The Report says that a program that breaks the lifetime rule is wrong and that its further behavior is undefined, which allows but does not require an implementation to check it. Algol 68 Genie checks: it warns at compile time and stops the program with the error “value is exported out of its scope”. ga68 and a68j do not check, and such a program may even appear to work, which makes the error all the more dangerous. Use heap for anything that must outlive its block.

The lifetime of a loc cell

loc is an expression like any other and can appear anywhere a reference is needed, for example as a dummy argument for a ref parameter whose result is not wanted. The precise rule for its lifetime has a surprising consequence. A loc cell belongs to the nearer of two things: the function or operator body in which it is allocated (every call counts), or the innermost block, loop body or other range that declares a variable, a constant, a function, an operator or a type. Ranges without such declarations do not count, nor do the loop counter, the name in an alternative of a conformity clause, labels and priority declarations. Every call of a function counts, even if its body declares nothing: proc f = ref int: loc int := 0 returns a reference to a cell that is gone when the call is over. The following program keeps references to cells allocated in a loop body:

[3] ref int cells;
for i to 3 do
   int square = i * i;
   cells[i] := loc int := square
od;
print ((ref int (cells[2]), newline))

Algol 68 Genie stops it:

6           cells[i] := LOC INT := square
                        1                
a68g: runtime error: 1: REF INT value is exported out of its scope, in VOID long-symbol starting at "FOR" in line 4.

The loop body declares square, so every loc int belongs to one execution of the body and is gone when the next one starts. Without the declaration, writing cells[i] := loc int := i * i, the cells belong to the block around the loop, and the program is correct and prints 4. A harmless-looking change to the body thus changes the lifetime of the cells. The advice is simple: if a reference leaves the block or loop body in which its cell is allocated, allocate the cell with heap.

heap can also be used in declarations: heap int n := 5 and heap [10] int a declare variables whose cells live on the heap. There is no operation to free a heap cell; that is left to the garbage collector, which costs time and memory. The distinction is the one between the stack and the heap in C++ and Rust (Box); Java and Python allocate every object on the heap.

7.16 Lifetimes of functions

The lifetime rule also applies to functions, and this is where Algol 68 differs most from current languages. A function value lives as long as the innermost block that declares a name the function uses but does not declare itself: a variable, a constant, a parameter of an enclosing function, another function, an operator, a label it jumps to, or a type name with bounds. A function that uses such a name cannot be returned from that block or stored in a variable outside it.

In JavaScript, Python or Haskell, returning a function that composes two other functions is an everyday idiom. In Algol 68 it is an error:

mode Fn = proc (real) real;
proc compose = (Fn f, g) Fn: (real x) real: f (g (x));
proc double = (real x) real: 2 * x;
proc inc = (real x) real: x + 1;
Fn h = compose (double, inc);
print ((fixed (h (1), 0, 1), newline))

Algol 68 Genie stops at the call of compose:

7        FN h = compose (double, inc);
                1                     
a68g: runtime error: 1: FN value is exported out of its scope, in VOID closed-clause starting at "BEGIN" in line 1.

The inner function uses f and g, the parameters of compose, which exist only while compose runs. Putting the data on the heap does not help either:

proc int next = (heap int count := 0; int: count +:= 1)

The cell of count would live long enough, but the name count belongs to the block, and the function uses the name. Algol 68 Genie stops this program as well, with the same message; ga68 and a68j run both programs and print plausible results. Here the lack of a check is most dangerous, since such a program appears to work.

The reason for the rule is that an Algol 68 function does not keep alive the variables and constants it uses, as a closure in Lisp, JavaScript or Python does by keeping them on the heap; it refers to the block in which they are declared, which lives on the stack. A C++ lambda that captures by reference has the same problem, without any check; Rust rejects such a closure at compile time unless it is declared move.

The usual way out is to pass the state explicitly. A counter becomes a heap cell and a function that takes it as a parameter:

proc make_counter = ref int: heap int := 0;
proc next = (ref int counter) int: counter +:= 1;
ref int c = make_counter, d = make_counter;
for k to 3 do print ((whole (next (c), 0), " ")) od;
print ((whole (next (d), 0), newline))
1 2 3 1

which prints 1 2 3 1. A function that composes two functions becomes a procedure (Fn f, g, real x) real: f (g (x)) that receives all three values at each call. Where a function value must be kept, a record that holds the state together with a function that takes the state as a parameter does the job of a closure. Algol 68 Genie and a68j offer a further way out, partial parametrization, an extension of the language that Appendix G describes.

7.17 Recursive types

A type declaration may refer to the type it declares, which allows linked data structures. A list of integers is a chain of records, each of which holds a value and a reference to the next record:

mode Node = struct (int value, ref Node next);
ref Node no_node = nil;
ref Node list := no_node;
for i to 5 do list := heap Node := (i * i, list) od;     { prepend }
ref Node p := list;
while ref Node (p) isnt no_node do
   print (value of p);
   p := next of p
od;
print (newline)
        +25        +16         +9         +4         +1

The constant no_node is nil of the type ref Node; naming it makes the comparisons readable. The loop builds the list by putting each new record in front: heap Node := (i * i, list) allocates a record on the heap, initializes it, and yields the reference to it, which is stored in list. The second loop follows the references; value of p and next of p dereference p automatically. The records must be allocated with heap: with loc inside a procedure, the list would refer to cells that are gone when the procedure returns, and ga68 and a68j would not report it.

The recursion must pass through a reference or a function type. A record that contains itself directly would be infinitely large, and the compiler rejects it:

access Genie_Transput
begin
   mode Chain = struct (int value, Chain next);
   skip
end
bad-mode.a68:3:9: error: chain does not specify a well formed mode
bad-mode.a68:3:9: note: mode chain is infinite

Passing through a reference is not enough on its own, though: mode A = ref A or mode U = union (int, ref U) would make a type out of nothing but references, and they are rejected as well. The precise rule is that every cycle in a type definition must pass both through a reference or a function type, and through a record or a function type with parameters. struct (int value, ref Node next) satisfies it, and so does mode F = proc (F) int. The Report calls the admissible recursive types well-formed modes.

Several types can refer to each other, if they are declared in the same block:

mode Person = struct (string name, ref Dept dept),
     Dept = struct (string title, ref Person head);
heap Dept d := ("Research", nil);
heap Person p := ("Ada", d);
head of d := p;
print ((name of head of dept of p, " heads ", title of d, newline))
Ada heads Research

Pointers to links

The type ref ref Node is the type of a variable that holds a link: the variable list itself, or the field next of a node. A procedure that receives such a reference can change the link, which makes operations on lists simple. The following procedure removes the first node with a given value. It walks along the links, not along the nodes, so that the first node needs no special treatment:

proc remove = (ref ref Node head, int v) void:
begin
   ref ref Node link := head;   { the variable that refers to the node }
   while (ref Node (link) isnt no_node) andth value of link /= v do
      link := next of link
   od;
   if ref Node (link) isnt no_node then
      ref ref Node (link) := next of link
   fi
end;
2 4

After remove (list, 1), remove (list, 3), remove (list, 5) and remove (list, 9) on the list 1 to 5, the list holds 2 4. link is a pointer variable of type ref ref ref Node. ref Node (link) is the node that the current link refers to, and next of link is the link inside that node. The assignment ref ref Node (link) := next of link changes the current link so that it skips the node.

Pitfall.  The annotation decides what is assigned. With ref Node (link) := next of link, the left-hand side would be the node itself, and the assignment would copy the next node’s value and link into it: a different operation, which fails at the last node, whose next is nil. Both versions compile. When an assignment involves several levels of references, it pays to write down the type of each side.

7.18 Unions and recursive types

Unions and recursive types together describe tree-shaped data whose nodes are of different kinds: the syntax tree of a compiler, a document, a JSON value. An arithmetic expression is a number, a variable, or an operator with two operands:

access Genie_Transput
begin
   { Arithmetic expressions as trees. }
   mode Expr = union (real, char, ref Binop),
        Binop = struct (char sym, Expr left, right);

   proc bin = (char sym, Expr left, right) Expr: heap Binop := (sym, left, right);

   proc show = (Expr e) string:
      case e in
         (real r): fixed (r, 0, 1),
         (char name): name,
         (ref Binop b): "(" + show (left of b) + " " + sym of b + " "
                            + show (right of b) + ")"
      esac;

   proc eval = (Expr e, real x) real:
      case e in
         (real r): r,
         (char name): x,
         (ref Binop b):
            begin
               real l = eval (left of b, x), r = eval (right of b, x);
               char o = sym of b;
               if o = "+" then l + r
               elif o = "-" then l - r
               elif o = "*" then l * r
               else l / r
               fi
            end
      esac;

   { 3 x x - 2 x + 1 }
   Expr e = bin ("+", bin ("-", bin ("*", 3.0, bin ("*", "x", "x")),
                               bin ("*", 2.0, "x")),
                      1.0);
   print ((show (e), newline));
   for i from 0 to 3 do
      print (("x = ", whole (i, 0), ": ", fixed (eval (e, i), 0, 1), newline))
   od
end

prints

(((3.0 * (x * x)) - (2.0 * x)) + 1.0)
x = 0: 1.0
x = 1: 2.0
x = 2: 9.0
x = 3: 22.0

The type Expr is a union of real, char (the name of a variable) and ref Binop, and Binop is a record that contains two Expr values. The cycle passes through the reference and the record, so the types are well-formed. union (real, char, Binop) without the reference would be infinitely large and is rejected. In Rust the same type is written enum Expr { Num(f64), Var(char), Bin(Box<Binop>) }; the Box plays the role of ref.

show and eval are recursive functions with one alternative of a conformity clause per kind of node. The procedure bin allocates a node on the heap; its arguments are united to Expr automatically, since an argument is in a strong context.

Operators on unions

It is tempting to make the construction of expressions more readable with operators: op + = (Expr a, b) Expr: bin ("+", a, b), so that an expression can be written as 3.0 * x * x - 2.0 * x + 1.0. Declared in the program above, this operator takes over every + of two real values in its scope. The operands of an operator are in a firm context, where uniting is allowed, and the new + is declared in an inner block, so it hides the standard + of the library for real operands. l + r in eval then builds an Expr instead of adding, and the compiler reports

error: 'EXPR'mode cannot be coerced to 'real' in a strong-unit

Inside the body of an operator on a union, the effect can be worse: an op = = (union (int, Rational) a, b) bool whose body compares two int values with = calls itself, without end. The remedy is to declare an operator for each combination of member types that is needed ((Rational, Rational), (int, Rational), (Rational, int)), or to give the operator a new name, such as PLUS.

7.19 When two types are the same

Section 4.8 showed that type names are only abbreviations: two record types with the same fields are the same type. This also holds for recursive types. The types

mode A = struct (int v, ref A next);
mode B = struct (int v, ref B next)

are the same type, since expanding either definition gives the same infinite structure. Deciding this is a non-trivial task for the compiler, but it is invisible to the programmer. Together with the rules for unions, it means that two types are the same if and only if they have the same structure; the Report calls them equivalent modes.

7.20 A complete program

The final program counts the words of a text with a binary search tree. Each node holds a word, a count and two subtrees. The procedure insert takes a reference to the variable that holds a subtree, of type ref ref Tree, so that it can replace an empty subtree with a new node; show traverses the tree in order and prints the words alphabetically.

access Genie_Transput
begin
   { Counting words with a binary search tree. }
   mode Tree = struct (string key, int count, ref Tree left, right);
   ref Tree no_tree = nil;
   proc insert = (ref ref Tree t, string w) void:
      if ref Tree (t) is no_tree then
         t := heap Tree := (w, 1, no_tree, no_tree)
      elif w < key of t then insert (left of t, w)
      elif w > key of t then insert (right of t, w)
      else count of t +:= 1
      fi;
   proc show = (ref Tree t) void:
      if t isnt no_tree then
         show (left of t);
         print ((key of t, " ", whole (count of t, 0), newline));
         show (right of t)
      fi;
   ref Tree root := no_tree;
   string text = "the quick brown fox jumps over the lazy dog the end";
   string w := "";
   for i to UPB text + 1 do
      if i > UPB text orel text[i] = " " then
         (UPB w > 0 | insert (root, w); w := "")
      else
         w +:= text[i]
      fi
   od;
   show (root)
end
brown 1
dog 1
end 1
fox 1
jumps 1
lazy 1
over 1
quick 1
the 3

The test ref Tree (t) is no_tree uses the cast of Section 7.9: t is a reference to a variable, and the question is whether the variable holds nil. In show, the parameter is the tree itself, so t isnt no_tree needs no cast. The splitting loop uses orel (Section 2.9) so that text[i] is not evaluated when i is beyond the end.

7.21 A larger example: a JSON parser

The programs so far have been short, each one showing a few features. This section combines the features of this and the earlier chapters in a program of about 230 lines. It has a parser that reads JSON text into a tree of values, a printer that writes the tree back with indentation, and an operator that selects parts of the tree. Section 7.18 mentioned JSON, the data format of most web services, as an example of tree-shaped data whose nodes are of different kinds. Algol 68 can describe such data directly.

The types

mode Json   = union (void, bool, real, string, ref Array, ref Object),
     Array  = struct (flex [1:0] Json elements),
     Object = struct (flex [1:0] Member members),
     Member = struct (string key, Json value),
     Error  = struct (int position, string message);

A JSON value is of one of six kinds, and Json is a union of six types. null is the value empty of type void (Section 7.8). true and false are bool values, and numbers are real. Arrays and objects are references to records on the heap. An object is an array of members, each a key with a value, kept in the order of the text. Error describes a syntax error found by the parser.

The types are recursive: a Json value can be a reference to an Array, which contains Json values. Every cycle passes through a reference and through a record, so the types are well-formed (Section 7.17). The shorter union (..., ref [] Json) would be rejected. Its cycle passes through a reference but through no record, like the cycle of union (int, ref U). So the record with its single field is needed to make the type well-formed. Since arrays and objects are held by reference, copying a Json value copies only the reference, as with the objects of Java or Python. Since the field is a resizable array, a record on the heap can grow while the parser fills it. In Rust the type would be written

enum Json { Null, Bool(bool), Number(f64), String(String),
            Array(Vec<Json>), Object(Vec<(String, Json)>) }

where Vec is a resizable array on the heap.

Growing an array

op +:= = (ref flex [] Json row, Json v) ref flex [] Json:
begin
   [UPB row + 1] Json longer;
   longer[: UPB row] := row;
   longer[UPB longer] := v;
   row := longer
end;
op +:= = (ref flex [] Member row, Member m) ref flex [] Member:
begin
   [UPB row + 1] Member longer;
   longer[: UPB row] := row;
   longer[UPB longer] := m;
   row := longer
end;

The operator +:= appends a value to a resizable array, like the function append of Section 7.1. As an operator it reads like the s +:= c of strings: elements of a +:= value. It is declared twice, once for each element type, because Algol 68 has no generic functions. The standard +:= for strings remains available, since an operator is chosen by the types of its operands (Section 5.8). Copying the array for every new element takes quadratic time in the number of elements. For large documents, the doubling of Section 7.3 would avoid that.

The parser

The parser works by recursive descent: there is one function for each kind of value, and it calls the functions for the parts of the value. The functions are declared inside parse and share the text and the current position pos, as the methods of an object share its fields:

proc parse = (string text) union (Json, Error):
begin
   int pos := 1;
   Error error;
   proc fail = (string message) void: (error := (pos, message); goto failed);

   proc skip_space = void:
      while pos <= UPB text andth (text[pos] = " " OR text[pos] = REPR 10)
      do pos +:= 1 od;
   proc peek = char: (skip_space; (pos <= UPB text | text[pos] | REPR 0));
   proc expect = (char c) void: (peek = c | pos +:= 1 | fail ("expected " + c));
   proc literal = (string w) bool:
      if pos + UPB w - 1 <= UPB text andth text[pos : pos + UPB w - 1] = w
      then pos +:= UPB w; true
      else false
      fi;

   proc value = Json:
      if char c = peek; c = "{" then object
      elif c = "[" then array
      elif c = """" then string_value
      elif c = "-" OR is_digit (c) then number
      elif literal ("true") then true
      elif literal ("false") then false
      elif literal ("null") then empty
      else fail ((c = REPR 0 | "unexpected end of text" | "unexpected " + c)); skip
      fi;

peek skips white space and yields the next character, or REPR 0 at the end of the text. expect checks one character and steps over it. The condition of the if in value declares c, which is visible in all branches (Section 3.5). The branches yield values of different types: a reference to an object or an array, a string, a number, a bool or empty. The if as a whole has the type Json, the result type of value, and each branch is united to it. The last branch calls fail, which never returns. Its type is void, so skip supplies a Json value; that value is never used.

proc object = ref Object:
begin
   ref Object o = heap Object;
   expect ("{");
   if peek /= "}" then
      members of o +:= member;
      while peek = "," do pos +:= 1; members of o +:= member od
   fi;
   expect ("}");
   o
end;
proc member = Member:
begin
   string key = string_value;
   expect (":");
   (key, value)
end;

proc array = ref Array:
begin
   ref Array a = heap Array;
   expect ("[");
   if peek /= "]" then
      elements of a +:= value;
      while peek = "," do pos +:= 1; elements of a +:= value od
   fi;
   expect ("]");
   a
end;

object and array create a record on the heap and append to its field while they read the elements. value calls array and array calls value. The functions are mutually recursive, and the depth of the recursion follows the nesting of the text. object and array are declared after value, which uses them. That works because a function declared with a function literal exists from the start of its block (Section 3.3).

member reads the key in a declaration of its own and checks the colon before the display (key, value) calls value. The parts of a display are evaluated in no particular order (Section 3.4). A display (string_value, value) might therefore read the value before the key.

proc string_value = string:
begin
   string s := "";
   expect ("""");
   while pos <= UPB text andth text[pos] /= """" do
      if text[pos] = "\" andth pos < UPB text then
         pos +:= 1;
         char e = text[pos];
         s +:= (e = "n" | REPR 10 |: e = "t" | REPR 9 | e)
      else
         s +:= text[pos]
      fi;
      pos +:= 1
   od;
   (pos > UPB text | fail ("unterminated string"));
   pos +:= 1;
   s
end;

proc number = real:
begin
   int start = pos;
   proc next_is = (string chars) bool:
      pos <= UPB text andth char_in_string (text[pos], loc int, chars);
   proc digits = void:
   begin
      (NOT next_is ("0123456789") | fail ("digit expected"));
      while next_is ("0123456789") do pos +:= 1 od
   end;
   (next_is ("-") | pos +:= 1);
   digits;
   (next_is (".") | pos +:= 1; digits);
   (next_is ("eE") | pos +:= 1; (next_is ("+-") | pos +:= 1); digits);
   string s := text[start : pos - 1];
   File f;
   real x;
   associate (f, s);
   get (f, x);
   x
end;

string_value collects the characters up to the closing quotation mark. It turns the escapes \n and \t into a newline and a tab. Any other character after a backslash stands for itself, which covers \" and \\. In an Algol 68 string, a quotation mark is written twice, so """" is a single quotation mark; the backslash has no special meaning.

number checks the syntax of a JSON number: an optional minus sign, digits, optionally a point and more digits, and optionally an exponent. Each part is one line of code, so the function reads like the grammar. next_is uses the library function char_in_string (Appendix A). loc int serves as a dummy argument for the position, which is not needed (Section 7.15). The transput converts the digits into a real: associate turns the string into a file (Section 9.5), and get reads the number from it.

   Json doc = value;
   (peek /= REPR 0 | fail ("text after the value"));
   doc exit
failed:
   error
end;

The body of parse reads one value and checks that nothing but white space follows it. If all goes well, exit ends the body with doc (Section 3.9). If anything goes wrong, fail records the position and the message and jumps to the label failed. The jump leaves all active calls of value, array, object and the other functions at once, however deep the recursion is, and parse yields the error. Other languages use exceptions for this. In Algol 68 it is an ordinary jump to a label in an enclosing block, and fail can jump there because it is declared in that block. The result type union (Json, Error) is a union of seven types, since a union that contains a union contains its members (Section 7.7).

Printing

proc scalar = (Json v) bool:
   case v in (ref Array): false, (ref Object): false out true esac;
proc indent = (int depth) void: to depth do print ("  ") od;

proc show = (Json v, int depth) void:
   case v in
      (void): print ("null"),
      (bool b): print ((b | "true" | "false")),
      (real x): print (number_text (x)),
      (string s): print (quote (s)),
      (ref Array a):
         begin
            [] Json e = elements of a;
            bool flat := true;
            for i to UPB e do flat := flat AND scalar (e[i]) od;
            print ("[");
            for i to UPB e do
               (i > 1 | print (","));
               (flat | (i > 1 | print (" ")) | print (newline); indent (depth + 1));
               show (e[i], depth + 1)
            od;
            (NOT flat | print (newline); indent (depth));
            print ("]")
         end,
      (ref Object o):
         begin
            [] Member m = members of o;
            print ("{");
            for i to UPB m do
               (i > 1 | print (","));
               print (newline); indent (depth + 1);
               print ((quote (key of m[i]), ": "));
               show (value of m[i], depth + 1)
            od;
            (UPB m > 0 | print (newline); indent (depth));
            print ("}")
         end
   esac;

show is a conformity clause with one alternative for each kind of value; (void) is chosen for null. For arrays and objects, show calls itself for the elements with a deeper indentation. An array whose elements are all scalars is printed on one line. The test is scalar, a conformity clause without names. Two small functions turn numbers and strings into text:

proc number_text = (real x) string:
   if x = ENTIER x then whole (x, 0)
   else
      string s := fixed (x, 0, 6);
      while s[UPB s] = "0" do s := s[: UPB s - 1] od;
      { JSON wants a digit before the point }
      (s[1] = "." | "0" + s |: s[1] = "-" andth s[2] = "." | "-0" + s[2 :] | s)
   fi;
proc quote = (string s) string:
begin
   string q := """";
   for i to UPB s do
      char c = s[i];
      if c = """" then q +:= "\"""
      elif c = "\" then q +:= "\\"
      elif c = REPR 10 then q +:= "\n"
      else q +:= c
      fi
   od;
   q + """"
end;

number_text writes an integral number without a fraction. For other numbers it drops the trailing zeros of fixed. JSON requires a digit before the point, which fixed leaves out: fixed (0.5, 0, 6) yields .500000. quote writes the escapes back.

Selecting parts of a value

prio SEL = 9;
op SEL = (Json v, string k) Json:
   case v in
      (ref Object o):
         begin
            [] Member m = members of o;
            int i := 1;
            while i <= UPB m andth key of m[i] /= k do i +:= 1 od;
            (i <= UPB m | value of m[i] | empty)
         end
      out empty
   esac;
op SEL = (Json v, int i) Json:
   case v in
      (ref Array a): (i >= 1 AND i <= UPB elements of a | (elements of a)[i] | empty)
      out empty
   esac;

SEL selects a member of an object by its key or an element of an array by its index. It yields null if there is none, so that selections can be chained without checks: doc SEL "implementations" SEL 3 SEL "name". Operators of the same precedence are applied from left to right (Section 2.8), so the chain is read as ((doc SEL "implementations") SEL 3) SEL "name". The operator has two declarations, one with a string and one with an int as the right operand.

SEL needs a name of its own. An operator / with the operands Json and int would also be chosen for x / 2 with a real x, because the real operand is united to Json (Section 7.18). A key of one letter must be written string ("a"): "a" alone is a char, and no SEL takes a char (Section 7.8).

The main program

proc report = (string text) void:
   case parse (text) in
      (Json v): (show (v, 0); print (newline)),
      (Error e): print (("error at position ", whole (position of e, 0), ": ",
                         message of e, newline))
   esac;

   "{""language"": ""Algol 68"", ""years"": [1968, 1975], ""orthogonal"": true," +
   " ""successor"": null, ""implementations"": [" +
   "   {""name"": ""ga68"", ""target"": ""native code""}," +
   "   {""name"": ""a68j"", ""target"": ""JVM""}," +
   "   {""name"": ""Algol 68 Genie"", ""target"": ""interpreter""}]," +
   " ""authors"": [""van Wijngaarden"", ""Mailloux"", ""Peck"", ""Koster""]}";
case parse (algol) in
   (Json doc):
      begin
         show (doc, 0); print (newline);
         show (doc SEL "implementations" SEL 2, 0); print (newline);

            (string s): print (("first author: ", s, newline))

      end,

esac;

What the example shows

The parser combines several features:

  • tagged unions, with conformity clauses that check the type at run time;

  • recursive types on a heap whose memory is managed automatically;

  • nested functions that share the variables of their block;

  • operators with user-defined precedence;

  • a jump out of a deep recursion.

All of them belong to the language of the Revised Report of 1975. The program goes beyond it only in the short-circuit andth and in the transput of Genie_Transput. In the widely used languages, most of these features came decades later: std::variant with C++17, the match statement with Python 3.10 in 2021, and pattern matching over sealed types with Java 21 in 2023. A C version of the program would need a hand-written tag in every value and explicit memory management.

The program also shows the limits of the language. Algol 68 has no generic functions, hence the two +:= operators, and it has no exceptions, only jumps. A further limit comes from the implementations: with ga68 and a68j, real has single precision (Section 2.1), so a number with more than about seven significant digits loses its last digits. A parser for real use would keep long real values.

Programming problems

  1. Text in pieces. Keep a long text as a linked list of pieces, each a string, so that joining two texts only links their lists. Write procedures for joining, for the length, for the character at a given position, and for turning the list back into one string. Which operations are cheaper than with a single string, and which are more expensive?

  2. List operations. For the lists of Section 7.17, write procedures that return the n-th element, append a copy of one list to another, merge two sorted lists into one, and sort a list by repeatedly merging.

  3. Sets. Represent sets of integers as sorted linked lists, and write the operators + (union), * (intersection), - (difference) and ELEM (membership, as in 3 ELEM s). Then write the same operators for sets represented as bits (Section 6.3) and compare.

  4. Tree sort. Sort an array of integers by inserting its elements into a binary search tree and reading them back in order. Duplicates must be kept. What is the cost for an array that is already sorted?

  5. Postfix expressions. Read an expression in postfix notation (3 4 + 2 *) and evaluate it with a stack of real values implemented as a linked list.

  6. Parsing. Extend the program of Section 7.18: read a fully parenthesized expression such as ((3 * (x * x)) - (2 * x)), build its tree, print it, and evaluate it for several values of x.

  7. Symbolic differentiation. Write a procedure that returns the derivative of an Expr with respect to x, and a procedure that simplifies the result: 0 ⋅ e = 0, 1 ⋅ e = e, e + 0 = e, and operations on two numbers are computed.

  8. Optional results. Write a procedure that searches a list of (name, number) records for a name and returns union (int, void). Use it in a program that reads names and reports each one’s number or that it is unknown, with an out branch in every conformity clause.

  9. A hash table. Implement a table from strings to integers as an array [0 : m - 1] ref Entry of linked lists, with procedures to insert, look up and delete. Count the words of a text with it and compare the result with the tree of Section 7.20.

  10. Pascal’s triangle. Store the first 15 rows of Pascal’s triangle in a jagged array, once in a flex [1:0] flex [1:0] int that grows row by row, and once as a [15] ref [] int whose rows are allocated with heap.

  11. A deck of cards. Declare the 52 cards of a deck as a fixed array of records, each with a field ref Card next, and link them into a circle. A hand is a record with a count and a reference to its first card. Deal cards from the deck to four hands only by changing links, without copying a card. Why is it allowed here to keep references to elements of the array?

  12. A queue. Implement a queue as a record with references to its first and its last node, so that both adding at the end and removing at the front take constant time. Write a procedure that creates a candidate node on the heap and appends it only if it passes a test; what happens to a rejected node?

  13. Exact or approximate. Find the largest n whose factorial fits in an int, without causing an overflow. Then write a function that returns union (int, real): the exact factorial up to that n, and Stirling’s approximation beyond it. How must a caller use the result?

  14. More JSON. Extend the parser of Section 7.21. (a) Report errors with line and column instead of the position. (b) Accept the escape \u followed by four hexadecimal digits, using REPR. This works with ga68 and a68j; in Algol 68 Genie, max_abs_char is 255. (c) Write an operator EQ that compares two JSON values, where the members of two objects may be in a different order. (d) Add int to the union, for numbers without a point and an exponent. Which conformity clauses must change, and does the compiler point them out?

  15. Cross-reference. Read an Algol 68 program and build an index of its identifiers: a tree, sorted by name, whose nodes hold a list of the line numbers where the name occurs. Print the index in alphabetical order. Reserved words, which are written in lower case in SUPPER stropping, can be recognized with a table.
