Appendix H: Calling Java

What calling C is for ga68 (Appendix G), calling Java is for a68j. Since a68j compiles to the Java virtual machine, an Algol 68 program can use the classes of the Java platform directly: the static methods and fields of a class, and its objects with their constructors, methods and fields. This puts the large library of the JDK, and any library or class written in Java, at the disposal of the program. The program runs wherever a Java virtual machine runs, as other Java programs do. The facility is an extension of a68j and is enabled with the option -fnest-java; a program that uses it runs only with a68j. Without the option, a68j reports what ga68 reports for such a program: Java is not a valid language indication.

Formal holes

A Java method or field is named by a formal hole, written as for C, with the language Java and the full name of the class:

proc (real) real cbrt = nest Java "java.lang.Math.cbrt";
proc (int) string to_binary = nest Java "java.lang.Integer.toBinaryString";
proc ([] int) string show = nest Java "java.util.Arrays.toString";
long real math_pi = nest Java "java.lang.Math.PI";
print ((fixed (cbrt (27), 0, 3), " ", to_binary (42), " ", show ((3, 1, 4)), newline));
print ((fixed (math_pi, 0, 10), newline))
3.000 101010 [3, 1, 4]
3.1415926536

The program is run with the option:

$ java -jar a68j-backend.jar -fnest-java -run methods.a68

As for C, the type is not written in the hole but given by the context, and a formal hole may only be written in a strong context. A hole of a procedure type names a static method; a hole of another type, such as math_pi, reads a static field once, when the declaration is executed.

The difference from C is that Java classes describe themselves. a68j looks the method up when it compiles the program and checks that the declared type fits it. Here cbrt is declared with a real, a 32-bit number, and Math.cbrt takes and returns a double: a68j converts the values, where the C declaration of Appendix G would give wrong results. A declaration that no method fits is an error when the program is compiled:

proc (string) real cbrt = nest Java "java.lang.Math.cbrt";
print ((fixed (cbrt ("27"), 0, 3), newline))
nosuch.a68:4:30: fatal error: no public static Java method 'java.lang.Math.cbrt' fits the mode proc (string) real
compilation terminated.

If a class has several methods of the name that fit, the overloads of Java, a68j takes the one that needs the least conversion, and reports an error if two are equally good. The parameter types can also be written after the name of the method, as in nest Java "java.lang.String.join(CharSequence, Iterable)".

Types

The types of Algol 68 and Java correspond as follows:

Algol 68 Java
void (as a result) any result, which is discarded
bool boolean
char int (the character code) or char
int, long int int, long
bits int
real, long real float or double, double
string String
an array of these types a Java array, copied
ref to an array a Java array, copied back after the call
proc an interface with one abstract method
ref to a record with one field a Java object (see below)

Where Java expects an object of a class such as Object or Integer, a value of a simple type is passed as the corresponding object, and an object returned by Java is converted back.

Functions as parameters

Many Java methods take a function: a comparison for sorting, an action for each element, a function to integrate. In Java such a parameter has the type of an interface with a single abstract method, such as Comparator or DoubleUnaryOperator. An Algol 68 function of the matching type can be passed for it. Arrays.sort sorts the array names with a routine text that compares the lengths of two strings; since the parameter is a reference to the array, the sorted array is copied back:

proc (ref [] string, proc (string, string) int) void sort = nest Java "java.util.Arrays.sort";
[4] string names := ("Wirth", "van Wijngaarden", "Lindsey", "Koster");
sort (names, (string a, b) int: UPB a - UPB b);
for i to UPB names do print ((names[i], " ")) od;
print (newline)
Wirth Koster Lindsey van Wijngaarden

Java code of one’s own

Classes of one’s own are found on the class path given with the option -fjava-classpath. The class Events below keeps the functions it receives and calls them later, and it has a method that calls two functions while it runs: Newton’s method for a zero of a function f with the derivative df. The interface Handler is one of its own; a function of type proc (string, int) void fits it:

import java.util.ArrayList;
import java.util.List;
import java.util.function.DoubleUnaryOperator;

public final class Events {
    private Events() {}

    // An interface with one abstract method: an Algol 68 function fits it.
    // In Algol 68: proc (string, int) void
    public interface Handler {
        void handle(String event, int value);
    }

    private static final List<Handler> handlers = new ArrayList<>();

    // Keeps the handler, to call it later.
    // In Algol 68: proc (proc (string, int) void) void register
    //    = nest Java "Events.register"
    public static void register(Handler h) {
        handlers.add(h);
    }

    // Calls every handler registered so far.
    // In Algol 68: proc (string, int) void fire = nest Java "Events.fire"
    public static void fire(String event, int value) {
        for (Handler h : handlers) {
            h.handle(event, value);
        }
    }

    // Newton's method: f and its derivative df are Algol 68 functions.
    // In Algol 68: proc (proc (long real) long real, proc (long real) long real,
    //    long real) long real newton = nest Java "Events.newton"
    public static double newton(DoubleUnaryOperator f, DoubleUnaryOperator df, double x) {
        for (int i = 0; i < 50; i++) {
            double step = f.applyAsDouble(x) / df.applyAsDouble(x);
            x -= step;
            if (Math.abs(step) < 1e-15) {
                break;
            }
        }
        return x;
    }
}

and the Algol 68 program that uses it:

proc (proc (long real) long real, proc (long real) long real, long real) long real newton
   = nest Java "Events.newton";
long real root = newton ((long real x) long real: x * x - long 2,
                         (long real x) long real: long 2 * x, long 1);
print (("sqrt 2 = ", fixed (root, 0, 15), newline));

proc (proc (string, int) void) void register = nest Java "Events.register";
proc (string, int) void fire = nest Java "Events.fire";
int total := 0;
register ((string event, int value) void: print ((event, " ", whole (value, 0), newline)));
register ((string event, int value) void: total +:= value);
fire ("open", 1);
fire ("read", 41);
print (("total ", whole (total, 0), newline))
sqrt 2 = 1.414213562373095
open 1
read 41
total 42

The Java class is compiled with the Java compiler first:

$ javac -d classes Events.java
$ java -jar a68j-backend.jar -fnest-java -fjava-classpath=classes -run callbacks.a68

The second handler changes the variable total of the program each time fire calls it. Java receives Algol 68 functions only as values that the program passes to it; it has no way to find a function of the program by its name.

A function that Java keeps may be called after the block in which it was declared has ended. In a68j this works, since its blocks keep their names on the heap rather than on the stack, but it goes beyond the lifetime rule of Section 7.16, and a68j does not check it. The functions that ga68 passes to C are bound to the stack frame of their block (Appendix G).

Objects

A Java object is represented by a reference to a record with one field. Each Java class gets a type of its own, declared once:

mode List = ref List_object;
mode List_object = struct (int list_java_object);
proc List new_list = nest Java "java.util.ArrayList<String>::new";
proc (List, string) bool add = nest Java "java.util.ArrayList<String>::add";
proc (List) int size = nest Java "java.util.ArrayList<String>::size";
proc (List, proc (string, string) int) void sort = nest Java "java.util.ArrayList<String>::sort";
proc (List) string show = nest Java "java.util.ArrayList<String>::toString";
proc (string, string) int compare = nest Java "java.lang.String::compareTo";

List l = new_list;
add (l, "Wirth"); add (l, "van Wijngaarden"); add (l, "Lindsey"); add (l, "Koster");
sort (l, compare);
print ((show (l), " ", whole (size (l), 0), newline))
[Koster, Lindsey, Wirth, van Wijngaarden] 4

The two type declarations are a pattern. A Java object is a reference that refers to nothing in the Algol 68 program: it can be passed on, stored in variables and compared, but taking its value or assigning to it is a run-time error. The record is therefore never created, and its field is never used. It is there only to give List a type of its own. Algol 68 compares types by their structure (Section 4.8), and the names of the fields belong to the structure of a record; the unusual field name list_java_object makes ref List_object differ from every other type. The type of the field does not matter; int is merely the shortest choice.

The record could even be left out. With mode List = ref int the program still runs, but a List is then the same type as every int variable, and as every other class declared in the same way. The compiler would accept an int variable where a list is expected, and the mistake would show only at run time, with the message a name where a java.util.ArrayList is expected. With a type of its own for each class, the compiler finds such mistakes, and operators can be declared for each class separately.

The value nil is Java’s null, and is compares two objects as == does in Java. A name with :: refers to a constructor (::new), a method of an object, or a field of an object; the object is the first parameter. The type arguments in angle brackets say what the type parameters of a generic class stand for, as in Java: with ArrayList<String>, a declaration of add with an int parameter is an error when the program is compiled. A Java method can itself be the function that is passed: compare is the method compareTo of a String, whose object is its first parameter, and sort receives it as the comparison.

Exceptions

An exception that a Java method throws and does not catch ends the program with a run-time error, at the position of the call in the Algol 68 program:

proc (string) int parse = nest Java "java.lang.Integer.parseInt";
print ((whole (parse ("42") + 1, 0), newline));
print ((whole (parse ("12x"), 0), newline))
43
exception.a68:6: runtime error: Java exception java.lang.NumberFormatException: For input string: "12x"

The program stops with the exit status 134, as for the run-time errors of Algol 68 itself.

Programs compiled separately

With -d, a68j writes the compiled program to a directory instead of running it. The program is then run with the Java command, with the runtime of a68j and the classes it uses on the class path (separated by ; on Windows):

$ java -jar a68j-backend.jar -fnest-java -fjava-classpath=classes callbacks.a68 -d out
$ java -cp a68j-backend.jar:classes:out Callbacks
